# ADR 037: Two kinds of app, console and windowed, each with a launcher built for its kind

## Context and Problem Statement

Some Ruby apps run in a terminal: command-line tools and terminal UIs such as Rooibos's. Others open windows and want no terminal: Lota's games and Tokra's desktop apps. Each operating system tells them apart in its own way. On Windows, whether a program gets a console is the PE header's Subsystem field, fixed in the executable: a console program opens one, and a GUI program gets none, and neither PowerShell nor an interactive `cmd.exe` waits for it. macOS knows a windowed app as an `.app` bundle; a Linux desktop lists one by its desktop entry. PyInstaller names the two kinds *console* and *windowed*.

The launcher is compiled once per runtime, in Fledge's CI. How does one runtime give a Windows app the kind its developer asked for?

## Decision Drivers

- A windowed app on Windows opens no console, as `rubyw.exe` does not; a console app keeps its standard streams and its exit status.
- A windowed launcher that cannot start its app still tells the person why, with no console to print to.
- A console launcher carries nothing it does not use.
- Fledge uses maintained tools for what they do, and writes no file formats of its own (ADR 010).

## Considered Options

1. Two launchers in every Windows runtime, built from the same source: `launcher.exe`, a console program, and `launcherw.exe`, a GUI-subsystem one. `fledge build` ships the one the app's kind asks for, renamed to the app's name. RubyInstaller ships `rubyw.exe` beside `ruby.exe` this way, and PyInstaller a windowed bootloader beside its console one.
2. One launcher, whose PE Subsystem field `fledge build` flips for a windowed app.

## Decision Outcome

Chosen: option 1, because one program that serves both kinds must carry the windowed kind's message box: flipping the console launcher's subsystem would leave every console launcher importing USER32 and calling `MessageBoxW` for nothing.

An app's kind is `fledge.yml`'s `kind`, `console` by default or `windowed`, or each program's in a project of several (ADR 024). `launcherw.exe` is `windows.c` compiled with `-DFLEDGE_WINDOWED` and linked with `-mwindows`; it shows its own failures in a message box unless whoever started it captured standard error. The other launcher never ships. On macOS a windowed app is `NAME.app`, whose executable is the same launcher a console app uses, and on Linux a windowed app's folder gains a desktop entry and icons (`doc/contributors/design/desktop-apps.md`). A windowed app must have an identifier (ADR 008).

Confidence: high. The runtime build checks each launcher's subsystem and imports, and Delivery checks a windowed Windows app opens no console.

### Consequences

- Good, because a windowed Windows app starts with no console, and typed into a console it returns the console at once, as `rubyw.exe` does.
- Good, because the console launcher imports only Windows' kernel and its C runtime, and the windowed one adds only USER32.
- Bad, because every Windows runtime carries two launchers, and its build compiles and analyzes each source twice.
- Bad, because a windowed Windows app's standard streams reach no console: a developer who wants to see its output redirects it, as for `rubyw.exe`.
- Bad, because the kind is fixed when the app is built; changing it means building again.
- Neutral: a project of several programs has at most one windowed program, since a windowed program is a bundle on macOS that holds the runtime (ADR 024).

### Confirmation

- `tasks/runtime_builder/windows.rb` refuses a console launcher whose PE subsystem is not 3, a windowed one whose subsystem is not 2, and either one importing a DLL beyond KERNEL32, the universal C runtime, and, for the windowed one, USER32.
- `.github/scripts/deliver-windowed.ps1` checks a windowed app's subsystem is GUI and that it ran with no console; `deliver-console.ps1` types a windowed app into a console and requires the console back at once, with `rubyw.exe` as the reference in the Test (Windows) job.
- `.github/scripts/deliver-windowed.sh` checks a windowed app's bundle on macOS and its desktop entry on Linux.

## More Information

- PyInstaller's console and windowed bootloaders, RubyInstaller's `ruby.exe` and `rubyw.exe`, Tauri's `windows_subsystem = "windows"`, and Electron's apps: none of their windowed programs attaches to the console that started it.
- How the windowed launcher shows a message: `doc/contributors/design/launcher.md`, "Messages and exit statuses". What a windowed app's folder holds on each system: `doc/contributors/design/desktop-apps.md`.
