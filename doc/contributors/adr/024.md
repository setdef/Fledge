# ADR 024: Ship a Project's Several Programs in One Folder, With One Runtime

## Context and Problem Statement

A Ruby project often has several ways in that share one codebase: a command-line program, a terminal program, and a graphical program that share one save file, so a person can quit one and resume in another. `fledge build` makes one program per run, so three programs would be three folders, each with its own copy of the project, the runtime, and the gems, and three things for a person to download.

Two facts of the platforms bear on any answer. A program's kind is a property of its executable: on Windows, whether a console opens is the PE header's Subsystem field (ADR 037), and on macOS a windowed app is a bundle whose `Info.plist` names one `CFBundleExecutable`. And on macOS and Linux the launcher holds libruby, and Ruby takes its prefix from the file that holds libruby (ADR 001), so every launcher sits beside `lib/ruby`. How should one project ship several programs?

## Decision Drivers

- One download, one copy of the runtime, one copy of the project, and one set of gems.
- Programs that share files beside the project, or in a home folder, read each other's, as they do when run with `ruby` from one checkout.
- Each program keeps its own kind, name, icon, and identifier.
- A project with one program builds exactly as before.

## Considered Options

1. A renamed copy of the launcher for each program, over one shared folder, as PyInstaller's multipackage bundles share one `COLLECT` and Tauri's bundler puts every binary of a crate in one app with one main binary.
2. One launcher that takes the program to run as an argument.
3. A bundle of its own for each program, each with its own runtime, as Briefcase builds each app of a project.

## Decision Outcome

Chosen: option 1, because one launcher cannot be both a console program and a windowed one on Windows, nor a bundle's executable and a terminal command on macOS, and because a bundle per program copies the runtime this story exists to share.

`fledge.yml`'s `programs` lists each program's `path`, and its `name`, `kind`, `identifier`, and `icon`. The project keeps `name`, `version`, `publisher`, `copyright`, and `installers`, which describe the one thing a person downloads. Each program is a copy of the runtime's launcher named for the program, and finds its own section of `fledge.cfg` by its file name. A project has at most one windowed program: on macOS a windowed program is a bundle, which must hold its runtime to be dragged to Applications, signed, and sealed, so a second one would be a second runtime. The windowed program's installers hold the whole folder, so every console program installs beside it. `fledge build FILE` on one listed program builds that program alone, as Cargo's `--bin` and Briefcase's `-a` do.

Confidence: high. Delivery builds a console program and a windowed one into one folder on every desktop platform, and checks that a save one writes the other reads.

### Consequences

- Good, because a project of several programs ships as one folder and one installer, with one runtime, one project, and one set of gems.
- Good, because a project with no `programs` builds the same folder, `fledge.cfg`, and output as before.
- Bad, because each program costs a copy of the launcher: several megabytes on macOS and Linux, where it holds libruby, and tens of kilobytes on Windows, where Ruby is a DLL. That is small beside the runtime it saves.
- Bad, because a second windowed program is refused, and has to be built on its own. Lifting the limit costs a runtime in each bundle on macOS and an AppImage per windowed program on Linux.
- Bad, because a program renamed by hand in a folder of several finds no section and exits with 66, where a lone program runs under any name.
- Bad, because nothing puts a console program on a `PATH`, and an AppImage reaches its console programs only through `--appimage-extract`.

### Confirmation

`test/config_test.rb`, `test/app_test.rb`, and `test/assembly_test.rb` hold the keys, the names, the layout, and the refusals; `test/config_schema_test.rb` holds `programs` in the schema (ADR 023). `examples/programs` builds and delivers on every desktop platform (`.github/scripts/deliver-programs.sh` and `.ps1`): both programs run from the one folder, share one `app/` and runtime, and read each other's save.
