# ADR 029: What 1.0 Freezes

## Status
Accepted (requested). Agents wrote this ADR and may change it until 1.0 (AGENTS.md, Questions); from 1.0, changing what section 2 lists is a major version. It carries out item 1 of the 1.0 review's must-change list (`doc/contributors/research/2026-11-04-one-point-oh-surface.md`, section 5) for Plan 003's story "1.0". It widens ADR 019, section 2, which lists what a framework wrapper may rely on, into the contract for every developer, and it takes Ruby's version and the platform floors from ADR 028. It applies the maintainer's words of 2026-11-02 (no 1.0 until some unproven things are proven) and 2026-11-03 (from 1.0 a human releases Fledge on RubyGems.org; a minor release may add Rubies and change only a patch; dropping a Ruby or an operating system version takes a major) in `decisions.md`, and decides nothing they leave open.

## Date
2026-11-04

## Context

Plan 003 says 1.0 tells developers that the CLI, `fledge.yml`, and what a built app contains will not change without a major version. SemVer 2.0.0's first item says software that uses it "MUST declare a public API", and its eighth says a backward-incompatible change to that API increments the major version. Fledge had not declared one. Its Ruby classes carry RDoc and examples, which reads as a promise; ADR 019 lists what a wrapper may rely on, but not what it may not. A wrapper such as Lota's `lota fuse` that called `Fledge::CLI` in process, read `fledge.cfg`, or matched a `fledge build:` message would hold each against every refactor of 1.x.

Prior art, as the review cites it (section 1, fetched 2026-11-04):

- **Tauri 2** declares a configuration file, `tauri.conf.json`, whose schema is served per major and whose `$id` names the exact release, and a command; its Rust crates are a separate API with versions of their own. Its configuration has `bundle > iOS > bundleVersion` and `bundle > android > versionCode`.
- **Briefcase** declares `pyproject.toml`'s `[tool.briefcase]` tables and the `briefcase` command. It has `build` and, on Android, `version_code`, which overrides the code it derives from the version.
- **cibuildwheel** pins its build tools with each release, so upgrading cibuildwheel is how a project takes newer tools.

The review read every part of the surface and judged each for 1.x. This ADR is its first item: the two lists, the rules for adding to them, and the names held for later.

A change is *compatible* when every project that builds with 1.0 builds with a later 1.x to the same output, and every app it built behaves the same. Turning a refusal into an acceptance is compatible (a new key, a new value of `kind`, lifting an "at most one"). Changing a default, a file name, a printed line, or the meaning of a value Fledge accepts is not.

## Decision

### 1. The interface is the command and the files it reads and writes

Fledge's public API is `exe/fledge`: what you type, what `fledge build` reads from your project, and what it writes. `fledge --help` documents it, between the `####` and `###` lines of `exe/fledge`; the README and `lib/fledge/config.schema.json` describe the same thing. Code that calls Fledge calls the command, as a person or a CI job does.

### 2. Frozen for 1.x

Each item below changes only in a major version.

- **The command.** `fledge build [OPTIONS] [PATH]`, `fledge build ios|android [OPTIONS] [PATH]`, `--help` (`-h`, `-?`), `--version` (`-v`), `-o`/`--out`, `--sign`, and `--`, with their meanings and defaults (`.` for PATH, `dist` for `--out`). A bare word Fledge reads as a platform, today `ios` and `android`, is read as one; a folder of that name is written `./NAME` (section 5).
- **Exit statuses.** `fledge`: 0, 1 for a failed build, 2 for a usage error. A built program: its Ruby program's status, 66 when its entry, `fledge.cfg`, or its section of `fledge.cfg` is missing, 72 on Linux when a library `linux: system_libraries` lists is not on the computer (ADR 030), and 70 for other damage; `bin/ruby`'s 70 when it cannot run the app's launcher; the phone runtimes' `FLEDGE_RUBY_NO_APP` and `FLEDGE_RUBY_SOFTWARE` (ADR 002, section 3; ADR 024, section 8; ADR 026, section 3).
- **Standard output.** One path per line for the archive `fledge build` writes and then each installer, or a phone project's folder; `--help` and `--version` print there too. Nothing else goes to standard output: the checksum files beside them are not printed (section 4).
- **`fledge.yml`.** Every key, every value it accepts, every default, and the refusal of a key it does not know: `name`, `kind`, `identifier`, `version`, `icon` and its list of files for each target, `publisher`, `copyright`, `installers` and its default (`dmg`, `nsis`, `appimage`), `programs` and its keys, `ios` and `android` with `host`, and `linux` with `system_libraries` (ADR 030).
- **The schema's address.** `$id` and the modeline name the file at the release's tag (ADR 023, section 3), and that address keeps serving the release's file. Every release has its tag, before 1.0 and after (ADR 028, section 7), and no release's tag is ever deleted.
- **What `fledge build` writes.** The names of section 2.6 of the review: `DIR/NAME-PLATFORM/`, its archive (`.tar.gz`, or `.zip` on Windows), `NAME-arm64-darwin.dmg`, `NAME-PLATFORM-setup.exe`, `NAME-PLATFORM.AppImage`, `NAME-PLATFORM.deb`, beside each of the archive and those installers its checksum file, `FILE.sha256`, one line in `sha256sum`'s format (the hash in lowercase hex, two spaces, and the file's name), `DIR/NAME-ios/`, `DIR/NAME-android/`, and `DIR/CACHEDIR.TAG`.
- **What a built app holds.** `app/`, the project as copied (an app's code finds its files through `__dir__`); `notices/NOTICES.txt` and `notices/sbom.spdx.json`; each program's name and where it sits; on macOS a windowed program's `NAME.app`, with the console programs in the bundle of the first windowed program (ADR 024, section 4); on Linux `IDENTIFIER.desktop` and `share/icons/hicolor/`.
- **Where an installer puts the app.** Windows' `%LOCALAPPDATA%\Programs\NAME`, its shortcut's AppUserModelID, and its uninstall key `HKCU\...\Uninstall\IDENTIFIER` (ADR 009, section 3); a `.deb`'s package name, the identifier lowercased, and its folder `/usr/lib/IDENTIFIER` (ADR 021). Each system knows the app by its identifier, so changing `identifier` makes a new app as far as that system is concerned, and the help says so.
- **How a built app differs from `ruby main.rb`.** `Parity::JUSTIFIED` (`tasks/parity.rb`) and `MOBILE_JUSTIFIED` (`tasks/parity/mobile.rb`) may only shrink in 1.x. A new difference is a change in how Ruby behaves under Fledge, the surprise the maintainer's words of 2026-11-02 forbid; removing one is a bug fixed toward `ruby main.rb`.
- **Phone projects.** The project folder's names and `fledge/`; the paths in the templates that a host may replace (ADR 025, section 5); the `@@NAME@@` marks Fledge fills; and the embedding API, `fledge_ruby_run`, `fledge_ruby_run_app`, `fledge_ruby_add_extension`, and `fledge_ruby_forward_output` in `fledge_ruby.h`, and `org.setdef.fledge.FledgeRuby.startApp` on Android.
- **Releases and runtimes.** The tag form `vX.Y.Z`, with a prerelease in SemVer's form, such as `v1.0.0-beta.1` (ADR 028, section 7); the asset names `fledge-runtime-VERSION-PLATFORM.tar.gz`, `-dev.tar.gz`, `-NOTICES.txt`, `.spdx.json`, and `-lgpl-sources.tar.gz`, with VERSION Fledge's; `SHA256SUMS` in `sha256sum` format; `FLEDGE_RUNTIME_DIR` as a folder of those names.
- **Ruby's version and the platform floors**, as section 6 says.

### 3. Not frozen

Each item below may change in any release, with a CHANGELOG entry when a developer could notice.

- **Fledge's Ruby code.** `Fledge::CLI`, `Fledge::Config`, `Fledge::App`, and every other class and module under `lib/`, their methods, and their RDoc. They document how Fledge works, for its contributors. A wrapper runs `fledge build` as a command.
- **Standard error's wording.** Progress lines, warnings, and every `fledge build: ...` message improve from release to release. A wrapper tells success from failure by the exit status, and finds the files by standard output.
- **`fledge.cfg`.** `fledge build` writes it and the launchers of the same release read it; nothing else should. Its keys and sections may change in any release. Runtimes of another release named by `FLEDGE_RUNTIME_DIR` stay unsupported (ADR 024, Consequences).
- **The runtime's tree** below what Ruby itself answers: `RbConfig.ruby`, `RbConfig::CONFIG`, `Gem.dir`, `Gem.bindir`, and `__dir__`. An app that asks Ruby where things are keeps working when a folder moves.
- **The templates' contents.** The files a phone project starts from may change in any release; a host's copy of one is the developer's to keep in step, and the build names each copy it uses (ADR 025, section 5).
- **The caches.** `~/.cache/fledge/` and what it holds. On Windows a later release may move it to `%LOCALAPPDATA%`, which costs one download.
- **How Fledge is built and tested**: CI, `tasks/`, the runtimes' sources and pins, and the build-only companion's contents.

### 4. How 1.x adds

- A new option, key, value, `kind`, command, or environment variable is compatible, since today's parser and `fledge.yml` refuse every one they do not know.
- A new installer is opt-in for all of 1.x, as `deb` is (ADR 021): a new default would print a new line and need a new tool on a computer that built yesterday.
- A new icon size for a target is optional: a build that passed keeps passing.
- A new line on standard output comes only with a file the developer asked for, such as an opt-in installer. The built folder is not printed: a wrapper derives it from the archive's name. A file written beside every archive, as the checksum file is, is not printed either, and adding one is compatible: a wrapper that reads standard output sees the same lines, and derives the file's name from the archive's.
- The checksum file is written always, not behind an option: every package manager that installs a console app from a release names its SHA-256 (`doc/contributors/research/2026-11-04-package-managers.md`), and an option would cost a developer a flag for what each of them needs. It is one file per archive, as cargo-dist writes (`checksum`, "a .sha256 file for each archive", `axodotdev.github.io/cargo-dist/book/reference/config.html`) and GoReleaser writes with `split` (`{{ .ArtifactName }}.{{ .Algorithm }}`, `goreleaser.com/customization/checksum/`), and not one list per release, as GoReleaser's default `checksums.txt`: each platform's app is built on its own computer (ADR 010), and one list under one name would be written once on each. Its format is GNU coreutils' `sha256sum`, so `sha256sum -c` and `shasum -a 256 -c` check it, and `cat *.sha256` makes the list a release page shows. Ruby's own `Digest::SHA256` writes it: no tool on all three systems prints that format (macOS has `shasum`, Windows `Get-FileHash` and `certutil`), and the format is one line.
- A limit lifted ("at most one windowed program", one PATH, one `--sign`, one `host`) is compatible, as long as what a project with one builds stays the same. When several windowed programs come, the console programs stay in the first one's bundle.

### 5. Reserved for later

Each name below is held, so that the feature it names arrives under it and nothing else takes it first.

- **`ios: build`**, a whole number for `CFBundleVersion` and `CURRENT_PROJECT_VERSION`, and **`android: version_code`**, a whole number for `versionCode`, each overriding the number Fledge derives from `version`, as Tauri's `bundleVersion` and `versionCode` and Briefcase's `build` and `version_code` do. Today both stores see `1.0.0.pre.1` and `1.0.0` as one build, and a second upload of a version is refused. The derivation (`lib/fledge/mobile_project/ios.rb` and `android.rb`) stays the default, frozen; only the override is to come.
- **Runtime asset names with the Ruby's version**: `fledge-runtime-VERSION-ruby-X.Y.Z-PLATFORM.tar.gz` and the same `-ruby-X.Y.Z-` form for each companion asset, for the runtime of a Ruby minor that a 1.x release adds (section 6). Throughout 1.x, the names without it keep meaning the runtime of the Ruby minor 1.0 ships, 4.0 today.
- **Platform words in PATH.** A bare word that names a platform Fledge may write a project for (`ios` and `android` today; `visionos`, `tvos`, `watchos`, or another later) is read as that platform by every release that adds it. `fledge --help` says to write `./NAME` for a folder of such a name, so a developer who follows the help is never broken by a new platform. Briefcase reads `briefcase build iOS` the same way.

### 6. Ruby's version and the platform floors

ADR 028 sets both, from the maintainer's words of 2026-11-03.

Fledge has no default Ruby. An app gets the Ruby that runs `fledge build`: the runtime of that Ruby's major and minor version, at the patch level the release ships, and the build fails when the release has no runtime for that minor (ADR 028, section 3). Frozen for 1.x: that rule; every Ruby minor 1.0 has a runtime for, Ruby 4.0 today, which only a major drops; and the refusal of a Ruby whose minor has no runtime. A minor release may add a runtime for a new Ruby minor, under the reserved names of section 5, and may move each runtime to a newer patch of its minor, with a CHANGELOG entry. No release moves an app to a new Ruby minor; its developer does, by running that Ruby.

The platform floors are macOS 14 on Apple silicon, Windows 10 on x64 and Windows 11 on ARM64, iOS 15, Android 8.0 (API 26), glibc 2.39, and musl 1.2. The first five are operating system versions; glibc's and musl's are C library versions, which ADR 028, section 5, treats as Linux's operating system versions, since raising one drops whole distribution releases. Raising any floor is a major, always, even when a store's rule forces it. A patch within a version is not a floor. Google Play's target API level and the Xcode version App Store uploads need live in the phone templates (section 3) and are not floors.

## Consequences

- A wrapper knows what to hold Fledge to, and what not to read: the command, its output and statuses, and the files, not the classes or `fledge.cfg`.
- Fledge's contributors refactor `lib/` and reword messages freely in 1.x. The RDoc stays, for them.
- Before 1.0 the frozen list may still change, and the 1.0 review's other must-change items change it first: the schema's address (ADR 023, section 3), a windowed program's default name (ADR 024, section 1), the help's word on platform words, the count of Fledge's files in an app, and the Ruby an app gets (ADR 028, section 3).
- Every item in section 2 is a promise the gate does not check by itself. Each is already tested where it is built (the CLI's tests, the schema test, `Parity`, the Delivery jobs); a test that would let one change without a failure is a bug in that test.
- ADR 019, section 2, stays as the wrapper's view and defers to this ADR where the two differ.
