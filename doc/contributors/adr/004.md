# ADR 004: Every Runtime Passes a License Audit Before It Is Archived, and the Audit Writes Its Notices

## Context and Problem Statement

Everything in a runtime is copied into every app built with it, so the app's developer distributes all of it. The maintainer's rule is that a developer owes nothing beyond notices for what Fledge copies in (`decisions.md`, 2026-10-26, decision 8, and decision 24 for GNU MP), that an LGPL library ships only with the library's source on offer, never the app's ("Source offer for... the app? Or the LGPL'ed library? Former won't be liked, latter is fine and normal.", 2026-10-26, later), and that developers are told plainly what they owe ("As long as we're clear about that to app devs, that's great."). Asked about a page listing, per platform, what ships and what it asks, he said: "Better to automate this as part of the DevOps pipeline, yes?" (2026-10-26, later).

A runtime holds thousands of files from rv-ruby or RubyInstaller, a dozen libraries compiled into them, and about forty gems. Any pin that moves can bring in a new component or a new license. How does Fledge know that what it ships meets the rule, and tell developers so, without anyone remembering to check?

## Decision Drivers

- The rule must hold for the runtime as built, not as the build meant it to be.
- No runtime that breaks the rule may reach a CI artifact, a test, Delivery, or a release.
- The list of what ships, the notices, and the developers' page must not drift from what ships.
- The maintainer asked for automation, not documents kept by hand.

## Considered Options

1. **The runtime builder audits every runtime before it archives it,** and writes the runtime's notices, SBOM, and the licensing page from what the audit found.
2. **Notices kept by hand:** `notices/README.txt` and folders of license texts copied in, with `runtime/sources.yml` listing each source's notice. This is how runtimes were built before the audit.
3. **An audit as a CI job beside the build,** reading the runtimes the build made.

## Decision Outcome

Chosen: option 1, because it alone makes a runtime that breaks the policy impossible to produce. The audit runs inside `RuntimeBuilder#license`, after the recipe builds the runtime and before anything is archived, and raises naming every violation. A job beside the build could be skipped, or fall out of step with it (commit 76412b0). Notices kept by hand record what someone meant to ship, which is what the maintainer's "automate this" asks to replace.

The audit walks every file and gives each to a component of `runtime/licenses.yml` or to a gem whose specification the tree holds. It reads every compiled file's links with the system's own tools (ADR 013). It proves each component compiled into another file is still there, at its version, by a string in the file. It judges every component's SPDX expression against the policy in `Fledge::LicensePolicy`. From the same report it writes `notices/NOTICES.txt`, `notices/sbom.spdx.json`, and, across all platforms, `doc/licensing.md`. The model is cargo-deny's `licenses` check, which fails a Rust build on any dependency whose license is not allowed.

The policy covers Fledge's runtimes only. An app's own gems are its developer's (ADR 007). Fledge's own files in a runtime are MIT (`decisions.md`, 2026-11-07); the policy judges them notice-only, and marks them as Fledge's so that no LGPL library is linked into them.

Confidence: high. The audit has run on every runtime of every push since it landed, and CI shows it refusing planted GPL code and finding the real copyleft in the upstream trees.

### Consequences

- Good, because a pin that moves (a new rv-ruby, RubyInstaller, OpenSSL, or Rust) fails the runtime build until `runtime/licenses.yml` follows it, and then the licensing page until it is regenerated. No one has to remember.
- Good, because every app carries its notices and an SPDX SBOM, and every release publishes them beside each runtime.
- Good, because `runtime/licenses.yml` is the one place a component's license and notice are recorded.
- Bad, because the map is long and must be kept exact: every file must have an owner, and every compiled component an evidence string. A routine update costs a map edit.
- Bad, because each runtime grows by its SBOM, about 2 MB unpacked, and its NOTICES, a few hundred kilobytes.
- Bad, because the audit's rules are Fledge's own code, about 1,500 lines in `tasks/license_audit/`: no maintained tool judges a whole runtime tree this way.

### Confirmation

- `RuntimeBuilder#license` raises `LicenseAudit::Failure`, and `test/runtime_builder_test.rb` checks that a runtime with libxcrypt linked into `bin/ruby` or a GPL gem is refused.
- CI's "Licenses" jobs audit each built runtime again, validate its SBOM with `pyspdxtools`, and require the audit to fail on a planted GPL extension and a GPL gem.
- CI's "Licenses of the whole upstream tree" jobs require exactly the findings `.github/license-expectations/` lists.
- CI's "Licensing page is current" job fails when `doc/licensing.md` differs from the page the runtimes give.
