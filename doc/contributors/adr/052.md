# ADR 052: An App Declares the Files It Opens, and Is Offered for Them but Never Made Their Default

## Context and Problem Statement

A framework's way to make an app by dropping a project on another app (ADR 032) needs the system to hand that app what was dropped. Each system does it its own way. On Windows, a file or folder dropped on a program arrives in its arguments with nothing declared. On macOS, it arrives as an Apple event, and Finder offers the drop only to an app whose `Info.plist` declares document types that cover it. On Linux, a file manager passes paths to an app whose desktop entry lists their MIME types. Beyond drops, a person expects "Open With" to list an app for the files it opens.

The maintainer put drag-to-fuse in scope on 2026-11-04 (`decisions.md`): "Drag-to-fuse is a huge part of why LÖVE2D is successful; CLIs can be scary to newbies." How does an app say which files and folders it opens, and what may Fledge do to a person's choices about them?

## Decision Drivers

- One declaration in `fledge.yml`, written as each system reads it.
- Prior art: Tauri's `bundle > fileAssociations` and electron-builder's `fileAssociations`, with `ext`, `name`, `role`, `mimeType`, and macOS content types.
- A person's default app for a kind of file is the person's to choose, never an installer's.
- The app's code runs as under `ruby main.rb` (Design precedence 2).

## Considered Options

1. Tauri's and electron-builder's keys, with the app always ranked `Alternate` on macOS and, on Windows, only listed in each extension's "Open with", never set as its default.
2. The same keys, with the prior art's ranks: `LSHandlerRank` `Default` on macOS, and the extension's default set to the app on Windows, as Tauri's and electron-builder's installers set it.

## Decision Outcome

Chosen: option 1, because it offers the app for what it opens and leaves each person's defaults alone. Option 2 makes the app the default for an extension that another app may already open, which no person asked for.

A windowed app lists `file_associations`, each with a `name`, a `role` (`viewer`, the default, or `editor`), and its `extensions`, `mime_types`, and `content_types`, or `folders: true`. A console app may not, since only a windowed app has a bundle, a desktop entry, or a setup program to declare them in. macOS gets `CFBundleDocumentTypes` ranked `Alternate`. Windows' setup program writes a ProgID for each extension and lists it in the extension's `OpenWithProgids`, and a verb on every folder. Linux's desktop entry gets `MimeType=` and `%F` in `Exec`. Fledge does not turn macOS's Apple event into arguments: `ruby main.rb` gets none either, so the app receives it through its GUI library's event loop, as SDL3's `SDL_EVENT_DROP_FILE`.

Confidence: high for what each system is told, which Delivery reads back; medium for a drop on the app's icon in Finder or the Dock, which needs a person or a GUI library's event, and is not proven.

### Consequences

- Good, because the app appears in Finder's, Explorer's, and a file manager's "Open With" for what it opens, and a person's defaults never change.
- Good, because on Windows a drop needs nothing declared, and an app with no GUI library still gets the dropped path in `ARGV`.
- Bad, because an app that wants to be the default asks each person to choose it.
- Bad, because a macOS app with no GUI event loop does not see what was dropped on it.
- Bad, because `extensions` alone does nothing on Linux, where a desktop entry knows files only by MIME type, and Fledge writes no shared-mime-info package to define a new type.
- Bad, because an extension dropped from `file_associations` in a later version stays registered on Windows until the person removes it, since the uninstaller knows only its own version's list.

### Confirmation

`test/config_test.rb`, `test/mac_bundle_test.rb`, `test/nsis_test.rb`, and `test/desktop_entry_test.rb` hold the keys, the refusals, and each system's entries. Delivery reads them back on `examples/windowed_app`, which opens folders and its own reports: `.github/scripts/deliver-windowed.sh` reads the document types with `plutil` and asks Launch Services which apps it offers; `.github/scripts/deliver-installer.ps1` checks the registry holds the ProgID and no default, opens a file and a folder through the shell, and checks the uninstaller leaves none of it; `.github/scripts/deliver-deb.sh` checks `mimeinfo.cache` names the app after `apt install`.
