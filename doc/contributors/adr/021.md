# ADR 021: A .deb Installer for Windowed Apps on glibc Linux

## Status
Accepted (requested). Agents wrote this ADR and may change it (AGENTS.md, Questions). It applies the maintainer's words of 2026-11-02 in `doc/contributors/decisions.md` ("Go for .deb."), and carries out the `.deb` that ADR 009 left to "a developer who needs" one and Plan 003's "The installers developers expect" listed as the cheapest of the rest. ADR 009 chooses which installers an app gets and ADR 010 how they are built (each on its own platform, with that platform's maintained tool); this ADR adds one to both. ADR 030 amends section 3: a project that lists the libraries its gems load from the distribution gets a `Depends` on their packages too.

## Date
2026-11-02

## Context

A Debian or Ubuntu user installs software with `apt`, which tracks what a package put on the computer and removes exactly that. An AppImage (ADR 009) is a file to run, not an installation: it adds no menu entry of its own and `apt` knows nothing of it.

Prior art, read for this decision:

- **Briefcase** writes a `DEBIAN/control` file and runs `dpkg-deb`. `_package_deb` in `src/briefcase/platforms/linux/system.py` (at beeware/briefcase commit c760cf5b, lines 1330 to 1403) writes `Package`, `Version`, `Architecture`, `Maintainer`, `Homepage`, `Description`, `Depends`, `Section`, and `Priority` (lines 1367 to 1376), with `libc6 (>= GLIBC)` among the dependencies (lines 1355 to 1361), and then runs `dpkg-deb --build --root-owner-group PACKAGE_PATH` (lines 1384 to 1393), which makes every file root's whatever the builder's user. It requires a long description (lines 1334 to 1338).
- **Tauri's bundler** (tauri-apps/tauri at 31f29e19) writes the package format itself: `crates/tauri-bundler/src/bundle/linux/debian.rs` generates the control file (`generate_control_file`, lines 162 to 263), the `md5sums` file (lines 302 to 325), and the tar and `ar` archives (`create_tar_from_dir`, `create_archive`, lines 354 to 403) with Rust crates. It installs the program in `/usr/bin`, other resources in `/usr/lib/PRODUCT`, and the desktop entry and icons through `freedesktop` (lines 112 to 141), and names the package `PRODUCT_VERSION_ARCH.deb` with `amd64`, `arm64` for the architecture (lines 47 to 66). It leaves out `Depends` unless the developer lists some, and computes `Installed-Size` (lines 176 to 177).
- **Debian Policy** (https://www.debian.org/doc/debian-policy/): section 5.3 lists the binary package control fields, and marks `Package`, `Version`, `Architecture`, `Maintainer`, and `Description` mandatory and `Section` and `Priority` recommended; 5.6.7 gives the characters of a package name (lower case letters, digits, plus, minus, and full stops, at least two, beginning with an alphanumeric); 5.6.12 the version (`upstream_version` of alphanumerics and `. + - ~`, beginning with a digit, no hyphen without a Debian revision, a tilde sorting before the empty string); 5.6.20 `Installed-Size`, in KiB; 5.6.13 the description's synopsis and body; and 9.1.1 requires the Filesystem Hierarchy Standard's locations, relaxing only that a subdirectory of `/usr/lib` may hold "a mixture of architecture-independent and architecture-dependent files".
- **dpkg-deb(1)**: `--build DIRECTORY [ARCHIVE]` packs a tree whose `DEBIAN/control` is the control file, and `--root-owner-group` (dpkg 1.19.0 and newer) makes every entry root's.

## Decision

### 1. dpkg-deb builds the package; Fledge writes only its inputs

`Fledge::Deb` lays the built app's folder out as the package's tree, writes `DEBIAN/control`, and runs `dpkg-deb --build --root-owner-group TREE FILE`, as Briefcase does. Tauri's route, a tar and an `ar` writer, is the code ADR 010 removed for the other installers and is not taken: `dpkg-deb` is Debian's own maintained tool, in every Debian and Ubuntu, and on other Linux distributions in a package named `dpkg` (Fedora's `dnf install dpkg`, Arch's `pacman -S dpkg`). The control file is a text input to that tool, a stanza of nine lines, not a format reader or writer.

A computer without `dpkg-deb` fails the build with `fledge build needs dpkg-deb, which it could not run (...). Install dpkg, which has it, such as with sudo apt install dpkg (Debian and Ubuntu have it already) or sudo dnf install dpkg.`, as every missing tool does (`Fledge::Command`).

### 2. It is a fourth `installers` value, not a default

`fledge.yml`'s `installers` takes `deb` beside `dmg`, `nsis`, and `appimage`, and no new key. The default for a windowed app stays `dmg`, `nsis`, and `appimage`. ADR 009 followed Tauri in building every installer a platform has by default; a default that included `deb` would make every Linux computer without `dpkg-deb` (Fedora, Arch, and Alpine's glibc cousins) fail a build that passes today, to produce a package for a family that computer is not in. So a developer who ships to Debian and Ubuntu lists `installers: [appimage, deb]`, and the failure to find `dpkg-deb` comes only when they did.

A `deb` in the list is for the glibc Linux platforms, `x86_64-linux` (`amd64`) and `aarch64-linux` (`arm64`). On a musl platform it builds nothing, as `dmg` builds nothing on Windows from the same list, so one `installers: [dmg, nsis, appimage, deb]` serves every platform's build, as `examples/windowed_app`'s does. The file is `NAME-PLATFORM.deb`, named after the archive as every installer is (ADR 009), not Debian's `PACKAGE_VERSION_ARCH.deb`, so a script finds it by platform.

### 3. The package's contents and metadata come from `fledge.yml`

- **Package** is the identifier in lower case (`com.example.CoolApp` is `com.example.coolapp`), which the identifier's letters, digits, and hyphens and the policy's package name rules (5.6.7) both allow. It is the app's identity and cannot collide with a distribution's package the way a name such as `cool-app` could, and it matches the desktop entry's and the icons' names, which already use the identifier (ADR 008, section 4).
- **Version** is the app's version, as Policy 5.6.12 spells it: RubyGems' pre-release `1.2.3.pre.4` becomes `1.2.3~pre.4`, which sorts before `1.2.3` as RubyGems sorts the first before the second.
- **Architecture** is `amd64` or `arm64`.
- **Maintainer** is `publisher` from `fledge.yml` (else the gemspec's authors, which is what `publisher` defaults to), else the app's name. Policy 5.6.2 asks for a name and an address in angle brackets; `fledge.yml` has no address, and `dpkg-deb` accepts the field without one. Adding an `email` key to give lintian what it wants is not needed to install, so is not added.
- **Description** is the app's name. Policy 5.6.13 requires a synopsis; `fledge.yml` has no description, and none is added for this. Tauri and Briefcase each have a description key; Fledge's `name` is what a software center shows beside the icon already. Amended 2026-11-05 (Plan 003, "What an app says about itself"): `fledge.yml`'s `description`, one line, is the synopsis when it is set, and `long_description` the extended description after it, each line after one space and an empty line as ` .`, as 5.6.13 writes them; `homepage` is a `Homepage` field (5.6.23). A project without them writes the stanza above, byte for byte.
- **Depends** is `libc6 (>= 2.39)` (`Platform::GLIBC_MINIMUM`, ADR 001, section 3). The runtime is built against that glibc, so `apt` refuses the package on an older Debian or Ubuntu, saying which dependency it cannot meet, where an `.deb` without it would install and fail when run. Nothing else is needed: the runtime carries its Ruby, OpenSSL, libyaml, libffi, zlib, and the LGPL libcrypt it replaces with (ADR 004); Briefcase lists `libpythonX` because its Python is the system's, and Fledge's Ruby is not.

  What an app's gems load at run time is another matter (2026-11-03). A gem that opens a library with `dlopen`, as SDL opens X11, Wayland, OpenGL, and the audio libraries it finds, names none of them in its compiled files, so neither the check of compiled files (ADR 013) nor anything else in Fledge can know them, and `apt` installs the `.deb` on a computer that lacks them, such as a server without X11. A desktop install of Debian or Ubuntu has them, and a windowed app is for a desktop. So `Depends` stays `libc6` alone, and the README and `fledge --help` say that the libraries a gem loads at run time are the desktop's. No `fledge.yml` key for more `Depends` was added then, because no developer had asked for one. Tokra asked on 2026-11-03, for WebKitGTK and GTK, which its extension links; ADR 030 adds `linux: system_libraries`, and the `.deb` depends on the packages dpkg-shlibdeps finds for them.
- **Section** `misc`, **Priority** `optional`, and **Installed-Size** (the regular files' bytes in KiB, rounded up, so `apt` can check the disk has room) complete the stanza.

The tree is the built folder at `/usr/lib/PACKAGE` (Policy 9.1.1 allows the mixture of files a Ruby runtime and an app are), with its desktop entry moved to `/usr/share/applications/IDENTIFIER.desktop` and its `share/icons` to `/usr/share/icons`, where desktops look, and nothing duplicated in `/usr/lib/PACKAGE`. The desktop entry's `Exec` is the program's full path, quoted as the specification asks, as the folder's own entry says to do when an entry is copied out of it (`Fledge::DesktopEntry`). No program is linked into `/usr/bin`: the app is windowed, started from a menu, and a name with spaces ("Hello Window") is no command; `Fledge::Deb` can link one if a developer asks. There are no maintainer scripts: the desktop and icon caches are updated by the triggers `desktop-file-utils` and the icon theme tools register, and the app writes nothing under `/usr/lib` when it runs, so removing the package removes everything it installed.

Amended 2026-11-05 (Plan 003, "A license text with the app"): with `fledge.yml`'s `license_file`, the tree holds `/usr/share/doc/PACKAGE/copyright`, the file's text, which Debian Policy 12.5 (Policy 4.7.4.1, `ch-docs.html`, read 2026-11-05) asks every package to carry as "a verbatim copy of its distribution license(s)", a file that "must neither be compressed nor be a symbolic link" and must be UTF-8, which the build checks. With `linux: deb_changelog`, it holds `/usr/share/doc/PACKAGE/changelog.gz`: Policy 12.7 names a package's one changelog `changelog.gz` "because there is no separate upstream maintainer", which is a Fledge app's case (its developer writes both), rather than `changelog.Debian.gz`, and asks that "all of these files should be installed compressed using `gzip -9`". Fledge runs `gzip -n -9`, the system's gzip, whose `-n` leaves out the file's name and time, so the same changelog makes the same bytes, as Debian's own `dh_compress` does; it writes no gzip itself. Files are 0644 and folders 0755, root's through `--root-owner-group`. Neither is written without its key, so a project without them builds the same tree. A license identifier (`License:` of a machine-readable copyright file, DEP-5) is not written: Fledge copies the developer's text as it is, and Policy 12.5 does not require that format.

### 4. Delivery installs it on a fresh Debian and Ubuntu, runs it, and removes it

`.github/scripts/deliver-deb.sh` runs in `debian:trixie-slim` (glibc 2.41) and `ubuntu:24.04` (glibc 2.39, the oldest the package's dependency allows) containers on `ubuntu-24.04` and `ubuntu-24.04-arm` runners, which hold no Ruby. It reads the fields with `dpkg-deb`, installs the file with `apt-get install`, which resolves the `libc6` dependency; checks the files, the desktop entry with `desktop-file-validate`, and the icons; runs the installed program as root, as `nobody`, and in a hostile Ruby environment, expecting the exit status and report the AppImage's delivery does; removes the package with `apt-get remove`; and fails if the package is still installed, any of its files remain, or `dpkg --audit` reports anything.

## Consequences

- A Debian or Ubuntu user installs a Fledge app with `sudo apt install ./Cool\ App-x86_64-linux.deb`, finds it in their menu with its icon, and removes it with `sudo apt remove com.example.coolapp`.
- A developer asks for it with `installers: [..., deb]`; the default is unchanged, so no existing build changes.
- The `.deb` is unsigned. `apt` installs a local file without a signature, and a repository is a distribution channel Fledge does not run.
- Not yet: `.rpm` (rpmbuild, the same shape), a `/usr/bin` link, a maintainer address, and `Recommends` and `Suggests`. A description, a homepage, a copyright file, and a changelog came on 2026-11-05 (section 3).
