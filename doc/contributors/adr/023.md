# ADR 023: Write fledge.yml's JSON Schema by Hand, and Test It Against Config

## Context and Problem Statement

`Fledge::Config` refuses an unknown key in `fledge.yml` and checks each value, but a developer learns of a mistake only when `fledge build` runs. Editors that run Red Hat's YAML language server (VS Code's YAML extension, and others that start the same server) complete keys, show descriptions, and mark mistakes as the developer types, once the file names a JSON Schema. The server's README (redhat-developer/yaml-language-server at 7e8061c7) says it reads draft-04, draft-07, 2019-09, and 2020-12 (line 9), and that a file names its schema with a modeline comment, `# yaml-language-server: $schema=<schema-url-or-path>` (lines 81 to 95).

A schema is a second statement of what Config enforces. How are the two kept from disagreeing?

## Decision Drivers

- The schema must accept exactly what Config accepts, and a change to either must fail until the other agrees.
- Config is Ruby that checks each value and raises with a message, not a set of types.
- Less code to keep: of two designs that both hold, the smaller one.
- Nothing Fledge ships may load what the check needs.

## Considered Options

1. Write the schema by hand, and test it against Config.
2. Generate the schema from Config with a rake task, check the result in, and fail the gate when it is stale, as Tauri generates `tauri.conf.json`'s schema from the Rust types its configuration is parsed into, and as `tasks/licensing_page.rb` keeps `doc/licensing.md`.

## Decision Outcome

Chosen: option 1, because it is the smaller design and still fails on every disagreement. `lib/fledge/config.schema.json`, draft-07, is the one place its facts are stated. `test/config_schema_test.rb` compares its keys, kinds, installers, default installers, identifier pattern, and identifier length with Config's constants. It runs a table of documents through both the schema and Config (with `Fledge::Identity`), and fails when either accepts what the other refuses. It reads patterns as ECMA-262 does, as editors do. It also checks the schema against draft-07's meta-schema, and checks every `fledge.yml` in the repository against both. `doc/contributors/design/public-interface.md` says what the schema holds.

Confidence: high. The test fails on any drift either way, and every key added since went through it.

### Consequences

- Good, because a developer who adds the modeline gets completion, descriptions, and errors in the editor.
- Good, because a new key, kind, or installer, or a changed rule, fails the test until the schema says the same.
- Good, because a RubyGems upgrade that changes what it reads as a version fails the test's version cases.
- Bad, because the test's table of documents grows with each new rule, and someone writes each rule twice, in Ruby and in JSON.
- Bad, because the test needs json_schemer (MIT, with hana, regexp_parser, and simpleidn, all MIT, and bigdecimal, Ruby's license), a development dependency pinned in the Gemfile and lockfile. Nothing Fledge ships loads it.
- Neutral, because what the schema cannot hold (a file that is not YAML, a value `YAML.safe_load` refuses) is the language server's or Config's to report.

### Confirmation

`test/config_schema_test.rb`, in the gate.

## Pros and Cons of the Options

### Generate it from Config

- Good, because Tauri shows the pattern works where configuration is a set of types.
- Bad, because a generator could read `KEYS`, `KINDS`, `INSTALLERS`, `IDENTIFIER`, and `IDENTIFIER_MAX`, but every description, the version's pattern, the icon's refused extensions, the non-blank rule, and the rules between keys would sit in the generator as literals. The generator would be the schema written in Ruby, plus a task, a staleness check, and tests of its own.

## More Information

ADR 054 decides the schema's address. ADR 044 decides that configuration is an optional `fledge.yml`. Submitting the schema to SchemaStore's catalog, which would match every file named `fledge.yml` without a modeline, is a change in another project's repository, and is left to the maintainer.
