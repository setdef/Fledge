# ADR 009: A Windowed App Gets Its Platform's Installers Unless fledge.yml Says Otherwise, and a Console App Gets None

## Context and Problem Statement

A built app ships as an archive: a `.zip` on Windows and a `.tar.gz` elsewhere. A person unpacks it and runs the program. That is all a terminal tool needs, but not all a desktop app's people expect, nor all the operating systems need. Windows shows an app's toast notifications only when a Start menu shortcut carries its AppUserModelID (ADR 008), and a zip makes no shortcut. Mac apps are downloaded as disk images more than any other way, and notarization staples its ticket to a disk image (ADR 033). Linux users take an app as one AppImage more readily than a tarball to unpack. Tauri's users, whom Tokra serves, expect exactly these.

Which installers should a build write, and who chooses?

## Decision Drivers

- A windowed app should reach a person the way that person's system expects, with no extra step for its developer.
- What an app ships is a property of the app, which every computer that builds it should agree on.
- A terminal tool is installed by putting its program on a `PATH`, which none of these installers does.
- A default should not need a tool that some computers of the platform lack.

## Considered Options

1. Every installer the platform has, by default, for a windowed app, with `fledge.yml`'s `installers` to choose fewer or none, as Tauri's `bundle.targets` defaults to all.
2. Installers chosen by a command-line option.
3. Installers for console apps as well as windowed ones.

## Decision Outcome

Chosen: option 1, because it gives a windowed app what its people expect with no configuration, keeps the choice with the app as Tauri's targets are configuration, and keeps the installers off terminal tools, which none of them would put on a `PATH`.

`fledge build` writes, for a windowed app, each installer its platform has beside the archive: a `.dmg` on macOS, an NSIS setup program on Windows, and an AppImage on Linux. `installers: [dmg, nsis, appimage]` names the ones wanted, and `installers: []` none. A `.deb` is a fourth value, never a default (ADR 021). A console app gets none, and a console app's `fledge.yml` that lists any fails the build. There is no command-line option.

Confidence: high. Delivery installs each installer on a fresh computer and runs what it installed.

### Consequences

- Good, because a windowed app's developer gets the three installers with no configuration, and a Tokra app's toasts work on Windows once installed, since the setup program's shortcut carries the identifier.
- Good, because one `installers` list serves every platform's build: each build makes the ones for its own platform and ignores the rest.
- Bad, because a windowed build takes longer, compressing a disk image or a file system and running makensis; `installers: []` skips that.
- Bad, because an AppImage needs `mksquashfs` from squashfs-tools 4.4 or newer on the Linux computer that builds it (ADR 049), which a developer may have to install.
- Bad, because the default set is frozen for 1.x: a new installer joins only as an opt-in value (`doc/contributors/design/public-interface.md`).
- Neutral, because a console app reaches people through the package managers instead (`doc/package_managers.md`).

### Confirmation

`test/installers_test.rb` and `test/config_test.rb` hold the defaults, the per-platform choice, and the refusals. Delivery installs `examples/windowed_app`'s installers on fresh runners and runs the app from each: `.github/scripts/deliver-dmg.sh`, `.github/scripts/deliver-installer.ps1`, and `.github/scripts/deliver-appimage.sh`.

## More Information

- What each installer holds and how Fledge makes it: `doc/contributors/design/desktop-apps.md`, "Installers". The developer's view: `doc/desktop_apps.md`, "Make a windowed app".
- Each platform's installer is made on that platform, with that platform's tools (ADR 010), from NSIS's and AppImage's own releases (ADR 049).
- Not built, and waiting for a developer who needs one: `.msi` and `.rpm`, a per-machine NSIS install, NSIS in other languages, a disk image's background and window layout, closing a running copy of the app before reinstalling it, and installers for console apps.
