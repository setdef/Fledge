# ADR 039: A Runtime Is a Whole Standard Ruby, Pruned Only of What No Running Code Reads

## Context and Problem Statement

A runtime is copied into every app, so whatever it leaves out, an app cannot have. The maintainer set the bar: "When using fledge, your ruby source code should be able to be identical to how it was without Fledge, so the things you had to `require` before you can still need the app dev to `require`, but the things you didn't have to `require` before the app dev still shouldn't have to require." (`decisions.md`, 2026-10-26, decision 9), and "Tiny filesize is not a priority; "my ruby code just works" _is_ a (high) priority." (decision 20).

The walking skeleton's runtimes missed it. They left out Ruby's bundled gems (csv, bigdecimal, minitest, and the rest), so `require "csv"` failed in a built app and worked under `ruby`. macOS and Linux runtimes had no `bin/ruby`, so `RbConfig.ruby` and `Gem.ruby` named a program that did not exist. Later, ruby/spec's `library/mkmf` found that a runtime without Ruby's C headers makes `require "mkmf"` abort, with a message that names Ruby and a development package to a person who runs the app. What may a runtime leave out?

## Decision Drivers

- An app's Ruby code runs as it does under `ruby main.rb` (AGENTS.md, Design precedence 2).
- Nothing an app could require, load, read, or run may be missing.
- Size matters less (decision 20).

## Considered Options

1. **A whole standard Ruby:** every library, default gem, and bundled gem a standard Ruby installs, with their executables, `.gem` cache, build information, plugins, and C extensions, Ruby's own `ruby` program, and Ruby's C headers, pruned only of what no running Ruby code reads.
2. **The skeleton's runtime:** the standard library and default gems, without the bundled gems or `bin/ruby`, about half the size.
3. **Ruby's headers in the build-only companion only,** fetched when `fledge build` compiles a gem, and not in the runtime.

## Decision Outcome

Chosen: option 1, because it alone meets decision 9: an app finds every gem and library a standard Ruby has, and `RbConfig.ruby` runs. The skeleton's runtime broke `require "csv"`. Headers in the companion alone broke `require "mkmf"` at run time, which some gems do for `MakeMakefile#find_executable` (`mkmf.rb` at Ruby 4.0.9); the headers cost about 2 MB unpacked, and decision 20 says that does not count against "my ruby code just works".

What is pruned is only what no running code reads: documentation, the C headers of gems' extensions, static and import libraries, pkg-config files, debug symbols, and nkf's JRuby-only Java sources, which CRuby never compiles or loads. What a standard Ruby does not install is pruned too: rv-ruby's additions and RubyInstaller's tools for setting up a developer's computer. Each pruned thing has its reason in `RuntimeBuilder::Pruning`.

Confidence: high. The parity check compares the installed gems and whether each one's main file loads, on every platform, and ruby/spec runs in built apps.

### Consequences

- Good, because a developer's code that works under `ruby` finds what it requires in the app.
- Good, because `RbConfig.ruby` and `Gem.ruby` name a program that runs, so an app can start Ruby again.
- Bad, because runtime archives about doubled, and every app carries all of it: tens of megabytes before compression, more than a fused LÖVE game.
- Bad, because every bundled gem's license comes into every app; each is permissive, and the license audit checks each one's declared license on every build (ADR 004).
- Bad, because a runtime's `bin/ruby` is Fledge's own build of Ruby's `main.c`, which Fledge must keep, since rv-ruby's links libxcrypt statically (ADR 042).
- Neutral, because a phone app carries no headers and no `bin/ruby`, since a phone runs no program of its own; there an app that requires mkmf still stops (`doc/contributors/design/phone-runtimes.md`, "Ruby's C headers on a phone").

### Confirmation

- `tasks/parity.rb` compares the installed gems, whether each one's main file loads, and `RbConfig.ruby`, on every platform, and fails on a difference `Parity::JUSTIFIED` does not explain.
- `test/runtime_builder_test.rb` checks that pruning keeps every default and bundled gem, Ruby's programs, DLLs, and wrappers, and drops only what it lists.
- CI's ruby/spec job (`.github/workflows/ruby-spec.yml`, `tasks/ruby_spec.rb`) runs ruby/spec on stock Ruby and in a built app from the same runtime, and fails on an example that fails on one side only.
