# ADR 013: Read Compiled Files with the System's Own objdump, and llvm-readobj for PE

## Context and Problem Statement

Fledge asks compiled files a few questions. Which shared libraries does a file need? The license audit asks it of every file of a runtime (ADR 004), and `Fledge::Linkage` of every compiled file of an app's gems, so that a gem that would not load where the app goes fails the build (ADR 046). Which side-by-side assemblies does a Windows file's manifest name? What is the oldest macOS a Mach-O file runs on, and the newest glibc symbol an ELF file needs, for a gem Fledge compiles (ADR 091)? Is a Windows program a console or a GUI program?

Fledge answered these by parsing ELF, Mach-O, and PE itself, in about 550 lines of Ruby. The maintainer's words of 2026-10-28 rule that out: "Code is a liability and we should _not_ have 4k+ lines of things we could use existing tools for." (`decisions.md`). Which maintained tool reads each format, on each computer that builds apps?

## Decision Drivers

- Write no reader of a format a maintained tool already reads (AGENTS.md, How to work).
- Each platform's app is built on that platform (ADR 010), so each computer needs a reader of its own format only, and the license audit needs one of every format.
- Download nothing large to a developer's computer, and pin what is downloaded.
- Read PE's delay import table, which the audit resolves.

## Considered Options

1. **The system's own objdump for ELF and Mach-O, and llvm-readobj for PE.** `objdump -p` prints one form for ELF and Mach-O, from GNU binutils and from LLVM (Xcode's `objdump` is LLVM's), so one parser reads both. Windows has no reader, so the Windows runtime carries LLVM's `llvm-readobj`.
2. **llvm-readobj alone, everywhere,** with its JSON output for ELF.
3. **llvm-objdump alone.**
4. **readelf, otool, and vtool,** each system's specialist tool.
5. **llvm-mingw's tools in the Windows runtime,** rather than LLVM's own release.
6. **Keep the Ruby readers.**

## Decision Outcome

Chosen: option 1, because it needs no download on macOS or Linux, where the reader is already on any computer that compiles a gem, and one parser of one output form serves both formats. Fledge reads the tools' output, never the formats: `Fledge::Binary` picks out compiled files by their magic, as file(1) does, and hands them to the tool for their format.

The others each fail a driver. llvm-readobj everywhere would make Linux and macOS download LLVM (its releases there are about a gigabyte), or make every runtime carry it, where binutils and Xcode already have a reader. llvm-objdump omits PE's delay import table. readelf, otool, and vtool are three output forms for what objdump prints in one. llvm-mingw's llvm-readobj loads libLLVM, libc++, and libunwind, about ten times the size of LLVM's own static build. Keeping the readers is the code AGENTS.md says not to write.

Confidence: high. The license audit, `Fledge::Linkage`, and their tests read real files that clang and lld made, on every platform in CI.

### Consequences

- Good, because none of Fledge's code knows where a format keeps anything. A malformed or new kind of file is the tool's to read, and a new format version its maintainers'.
- Good, because the tests' fixtures are real linkers' output (`test/fixtures/binaries/build.rb`), not files Fledge's own writers made.
- Bad, because a Mac that builds an app with compiled gems needs Xcode's command line tools, and a Linux one binutils. A missing tool fails the build, saying what to install. Compiling any gem needs these anyway.
- Bad, because each Windows runtime carries `tools/llvm-readobj.exe`, about 8 MB, which the license audit must account for, and building that runtime needs 7-Zip, which `mise.toml` pins, to unpack LLVM's release.
- Bad, because the code that finds the tools, runs them in batches, and parses their output is not much shorter than the readers it replaced. Its gain is that it knows no format.
- Neutral, because a file of compiled code that no tool on the computer reads is a violation (`unreadable`), so the audit fails rather than pass code it did not read.

### Confirmation

- `test/binary_test.rb` reads the checked-in fixtures; the gate sets `FLEDGE_REQUIRE_READERS`, so no test of a format skips there.
- CI's "Licenses" jobs read every platform's runtime on one Linux runner with the pinned llvm-mingw's LLVM tools (`FLEDGE_LLVM`).
- The license audit checks `tools/llvm-readobj.exe` by SHA-256 (`runtime/licenses.yml`).
