# ADR 067: On a phone, a bundled gem's extension keeps every symbol but its Init function to itself

## Context and Problem Statement

On a phone, bundled gems with extensions stay gems, their extensions linked into the runtime's one library beside libruby (ADR 058). On Ruby 4.1, prism is a bundled gem whose extension compiles its own copy of libprism, and libruby holds a copy of its own, for its parser and for `Ruby::Prism` (`prism_init.c`, which registers `ruby/prism/prism.so`). Linked into one library, the two collide: ld.lld fails with "duplicate symbol: pm_parse" and every other `pm_` symbol. Fledge 0.12.0 left prism's extension out on iOS and Android, against ADR 058, so a phone app's `require "prism"` raises `LoadError`, and so does requiring irb, minitest, rbs, rdoc, repl_type_completor, or typeprof, which depend on it.

On a desktop the two copies never meet: the gem's extension is a shared object, Ruby looks up only its Init function in it, and its extconf.rb compiles it with `-fvisibility=hidden`, so it exports only `Init_prism` (prism 1.9.0, `ext/prism/extconf.rb`, line 108; libprism's functions are exported only under `PRISM_EXPORT_SYMBOLS`, `include/prism/defines.h`, lines 45 to 55, which the extension never sets). How can prism's extension link beside libruby's libprism, so that ADR 058 holds for prism?

## Decision Drivers

- ADR 058: every bundled gem with an extension is a gem on a phone, as on a desktop.
- An app's code runs as under `ruby main.rb` (AGENTS.md, Design precedence 2): `require "prism"` on a phone loads the prism gem a desktop loads, its Ruby and its extension.
- The two copies are not one library. Both say 1.9.0 (`prism/version.h`), but Ruby 4.1.0-preview1's `prism/` is a later libprism than the gem's: it allocates from an arena (`arena.c`, used 48 times in its `prism.c` and never in the gem's) and has `internal/` headers the gem lacks, the gem has a `pack.c` it lacks, and the files both have differ, `ast.h` by 3,347 lines and `prism.c` by 12,162 in `diff`. The gem's `lib/prism` is generated for its own nodes and serialization.
- Use the platforms' own tools, Xcode's and the NDK's, and write no tool a maintained one provides (AGENTS.md; decisions.md, 2026-10-28).

## Considered Options

1. Link each bundled gem's extension into one relocatable object (`cc -r`), then make every symbol it defines local but its Init function: Apple's `nmedit -s` on iOS, the NDK's `llvm-objcopy --keep-global-symbol` on Android.
2. The same, but making local only the symbols the extension hides (`llvm-objcopy --localize-hidden`, or Apple's ld, which makes hidden symbols local when it links with `-r`).
3. Option 1 or 2 for prism alone, or with `objcopy --localize-symbol` for a list of libprism's names.
4. Rename libprism's symbols in the gem's build, with a prefix at compile time (a header of `#define`s, or `-D` options).
5. Build the gem's extension against libruby's libprism, leaving the gem's copy out.
6. Answer `require "prism"` with libruby's own extension, `Ruby::Prism`'s.

## Decision Outcome

Chosen: option 1, for every bundled gem's extension, because it gives each extension on a phone what Ruby uses of its shared object on a desktop: its Init function, with every other symbol its own. It needs no list of names, so a new libprism, or another gem that compiles a library libruby or another gem also holds, needs no change.

`RuntimeBuilder::BundledExtensions.relocate` writes the rules into each copied extension's `depend` file, which mkmf appends to the extension's Makefile: the static library mkmf archives holds the one relocatable object instead of the objects. The Init function is the one extmk names for the extension's feature (`ext/extmk.rb`, line 565 at 4.1.0-preview1), so the gem's `Init_prism` is `Init_prism_prism`, which does not meet libruby's `Init_prism`. Each extension is also compiled with `-fno-common`, as mkmf compiles its shared object on a Mac (`CCDLFLAGS`) and as GCC and Clang compile by default elsewhere: for iOS, Xcode's clang made prism's `VALUE rb_cPrism;` and its other globals without an initializer common symbols, which neither tool can make local and which the linker would merge with the globals of the same names in libruby's own prism extension.

Option 2 was built first and failed on iOS: the iOS runtime compiles everything with `-fvisibility=hidden`, which hides the Init functions of bigdecimal, debug, nkf, racc, rbs, and syslog, whose sources do not export them, so the link of Ruby's `ruby` found none of them. Option 3 does the same with a special case, or with a list that changes with every libprism. Option 4 edits the gem's build for every one of libprism's hundreds of names. Option 5 fails on the drivers: the two libprisms are not API-identical, so the gem's extension would be compiled against headers it was not written for. Option 6 gives an app another prism: `Ruby::Prism`'s API "may change incompatibly between Ruby minor versions" (`prism_init.c`), and the gem's Ruby would not be the code that runs.

Confidence: high that it works, from the checks under Confirmation. No recorded comparison weighs it against option 4 beyond the size of the change.

### Consequences

- Good, because ADR 058 holds for prism: `require "prism"` and the gems that depend on it work on a phone as on a desktop, and `Parity::MOBILE_JUSTIFIED` no longer excuses them.
- Good, because one rule covers every bundled gem with an extension, with the platforms' own linkers, Apple's nmedit, and the NDK's llvm-objcopy.
- Bad, because every bundled gem's extension on a phone is linked one step more than before, and a new Ruby means checking that mkmf's static rule still archives `$(OBJS)` and extmk still names the Init function so. A wrong name fails the link of Ruby's `ruby` at once, on both phones.
- Bad, because an extension that meant another extension to call one of its functions could no longer; no bundled gem's does.
- Neutral: a phone app carries two libprisms, as a desktop process that loads the gem does.

### Confirmation

`test/bundled_extensions_test.rb` builds a fake prism with this computer's mkmf and compiler, its Init function hidden, with the rules `relocate` writes and the recipe of the phone built on the same system, links it into a program that has its own `pm_parse`, and checks that each calls its own. `test/fixtures/mobile_hello` requires prism and prints what it parses, which the Mobile apps jobs check on the iOS Simulator and on Android emulators (`MobileParity::HELLO`), and the mobile parity check fails when prism or a gem that depends on it does not load. On Android, `libfledgeruby.so` links every extension with `--whole-archive`, so any duplicate symbol fails the runtime's build.
