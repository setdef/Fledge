# ADR 057: Name phone targets so that no desktop gem fits them

## Context and Problem Statement

Fledge names a desktop target by its RubyGems platform (`doc/contributors/design/runtimes.md`, "Platform names and asset names"), so Bundler and RubyGems pick each gem's build for it. A phone breaks that. RubyGems knows no iOS: a name whose system is `ios` reads as an unknown system (`arm64-unknown`), and one that says `darwin` reads as macOS. Ruby built for iOS reports `RUBY_PLATFORM` `arm64-darwin`, as macOS does, so its own `Gem::Platform.local` matches every `arm64-darwin` gem. Bundler, resolving a lockfile there, would pick nokogiri's macOS build, which can never load on a phone. How are a phone's targets named, so that no desktop gem is ever chosen for one?

## Decision Drivers

- No precompiled desktop gem may reach a phone, where it cannot load (precedence 1).
- The app's Ruby code behaves as under `ruby main.rb`: `RUBY_PLATFORM =~ /darwin/` stays true on a system that is Darwin (decision 10).
- Ruby's `configure.ac` does for a Darwin host what an iOS build relies on, as xord/cruby's and the spike's builds do.
- Names follow RubyGems' grammar (`Gem::Platform#initialize`, `lib/rubygems/platform.rb` at Ruby 4.0.9): CPU, system, then what RubyGems calls the version.

## Considered Options

1. Fledge's own target names in RubyGems' grammar that no desktop name matches: `arm64-ios` and `arm64-ios-simulator`, after Apple's triples without the vendor; `aarch64-linux-android` and `x86_64-linux-android`, Ruby's own `RUBY_PLATFORM` there. Ruby keeps reporting `arm64-darwin` on iOS, and the app's Bundler runs with `force_ruby_platform`.
2. Configure Ruby for an `ios` host, so that `RUBY_PLATFORM` itself says `ios`.
3. Take another project's names as they are: Apple's `arm64-apple-ios` and `arm64-apple-ios-simulator`, PEP 730's (the same), or Rust's `aarch64-apple-ios` and `aarch64-apple-ios-sim`.

## Decision Outcome

Chosen: option 1, because it keeps Ruby's own platform true to the system and still keeps desktop gems out where Fledge decides. Configuring for an `ios` host leaves out what Ruby's `configure.ac` does for Darwin, and an app's own `RUBY_PLATFORM =~ /darwin/` would stop matching a Darwin system. Apple's, PEP 730's, and Rust's names carry a vendor or an abbreviation that RubyGems' Linux names drop (`aarch64-linux-android`, not `aarch64-unknown-linux-android`); option 1 drops the vendor the same way. The Android names are Ruby's own, which Gem::Platform reads as Linux with Android's C library, and which no `-linux`, `-gnu`, or `-musl` gem fits, rightly, since bionic loads none of them.

Since no gem publishes a phone build, `fledge build` refuses every precompiled build for a phone and writes Bundler's own `force_ruby_platform` into the app's `.bundle/config`, which Bundler documents as "Ignore the current machine's platform and install only `ruby` platform gems" (`lib/bundler/man/bundle-config.1.ronn`, at Bundler 4.0.20). An iOS Ruby then never resolves a macOS gem.

Confidence: high. `Gem::Platform.new("arm64-darwin") === Gem::Platform.new("arm64-ios")` is false, and so for every desktop name and every phone target.

### Consequences

- Good, because a gem with a precompiled desktop build ships its `ruby` build on a phone, which Fledge compiles from source (ADR 022).
- Good, because an app's code sees the platform Ruby reports on that system, as `ruby main.rb` would there.
- Bad, because the app's lockfile must lock `ruby` (`bundle lock --add-platform ruby`), and a build says so when it does not.
- Bad, because Fledge's iOS names are its own: no RubyGems tool knows them, and a gem cannot publish a build for them.
- Neutral: `RUBY_PLATFORM`, `RUBY_DESCRIPTION`, and the load path's platform folders differ from a desktop Ruby's, which `Parity::MOBILE_JUSTIFIED` in `tasks/parity/mobile.rb` justifies.

### Confirmation

`test/mobile_runtime_test.rb` checks that no desktop platform matches any phone target. `test/mobile_platform_test.rb` checks the lockfile names and `force_ruby_platform?`. The mobile parity check reports the platform names a phone's Ruby gives.
