# ADR 002: How fledge and a Built App Talk to the Person Running Them

## Status
Accepted (requested). Agents wrote this ADR and may change it (AGENTS.md, Questions). It follows the maintainer's decisions 4, 13, and 16 in `doc/contributors/decisions.md`: use the standards and prior art rather than ask.

## Date
2026-10-26

## Context

Two programs talk to people: `fledge`, which a developer runs, and the launcher inside every built app, which anyone runs. Each prints help or errors and exits with a status that scripts read. The first drafts of both were invented without citing anything: `fledge -V`, help on standard error with status 1 for a bare `fledge`, status 1 for every mistake, and status 70 for every launcher failure. The maintainer asked what the standards say, and whether there was prior art to follow instead of a question to answer (decisions 4 and 16).

The standards and the prior art:

- **GNU Coding Standards, section 4.8 ("Standards for Command Line Interfaces"), 4.8.1 (`--version`) and 4.8.2 (`--help`).** Every program accepts `--help` and `--version`; each prints to standard output and exits successfully, ignoring any other arguments.
- **Exit status 2 for usage errors.** The tools scripts test most give "you called me wrong" a status of its own, 2, apart from 1, "I tried and it failed": `grep`, `diff`, and `cmp`, whose statuses POSIX specifies; GNU `ls` (coreutils' `ls.c` passes `LS_FAILURE`, 2, to `usage`); and `bash`'s builtins. Other coreutils and most BSD `usage()` functions exit 1, a habit older than the distinction. sysexits.h offers `EX_USAGE` (64), which command-line tools rarely use. Fledge takes 2, the status that keeps the two kinds of failure apart and that scripts already expect from the tools above.
- **GNU's usage error message.** `ls: unrecognized option '--bogus'` then `Try 'ls --help' for more information.`, both on standard error. BSD tools print a one-line `usage:` synopsis instead. A short synopsis plus GNU's pointer serves both readers.
- **Ruby's own short options.** `ruby -v`, `gem -v`, and `bundle -v` print the version; `-V` means nothing to any of them. The maintainer's own Lota and Rooibos use `-v` too.
- **Windows habit.** `dotnet -?`, `winget -?`, and `cmd`'s `/?` print help; Windows users reach for `-?` first.
- **Ruby's own startup errors.** `ruby nowhere.rb` prints `ruby: No such file or directory -- nowhere.rb (LoadError)` to standard error: the program's name, a colon, and what went wrong.
- **sysexits.h** (FreeBSD's `sysexits(3)`, shipped by macOS and glibc). `EX_NOINPUT` (66): "An input file (not a system file) did not exist or was not readable." `EX_SOFTWARE` (70): "An internal software error has been detected." A program that is not Ruby itself cannot reuse Ruby's statuses, since an app's own failures already exit with whatever the app chooses (1 for an uncaught exception).

## Decision

### 1. fledge follows GNU's conventions, with Ruby's and Windows' short options

- `-h`, `-?`, and `--help` print the help to standard output and exit 0.
- `-v` and `--version` print `fledge VERSION` to standard output and exit 0.
- A bare `fledge`, an unrecognized option, an unknown command, and any mistake in a command's arguments (an unrecognized option, a missing value, two paths, an unknown target) are usage errors: the message, if any, as `fledge: ...` or `fledge build: ...`, then the short usage (the help header's SYNOPSIS) and `Try 'fledge --help'.`, all on standard error, with exit status 2.
- A build that fails (a missing app, a runtime that will not download, an app named like a runtime folder, a gem that cannot ship) prints `fledge build: ...` on standard error, one line per thing that is wrong, so one build names every gem it refuses (ADR 005), and exits 1. A warning, such as a gem that ships no license file, is `fledge build: warning: ...`.

`Fledge::UsageError`, a `Fledge::Error`, carries the second kind out of a command to `Fledge::CLI`, which owns the usage text.

### 2. fledge build's surface

These were open as a question; they are settled here, each by its prior art, and may change:

- **The built folder.** `NAME`, `fledge.cfg`, `app/`, `bin/`, `lib/`, `libexec/`, and `notices/` with `NOTICES.txt` and `sbom.spdx.json` from the license audit (ADR 004) on macOS and Linux; `NAME.exe`, `fledge.cfg`, `app\`, `notices\`, and RubyInstaller's tree in `ruby\` on Windows (ADR 001, section 8). A folder beside the program is what LÖVE's fused games and PyInstaller's one-folder bundles ship. A windowed app's folder holds `NAME.app` on macOS, and also `IDENTIFIER.desktop` and `share/icons/` on Linux (ADR 008).
- **The archive.** `.zip` for Windows, which Explorer opens with a double-click and no other software, and `.tar.gz` elsewhere, which keeps executable bits and symbolic links, as python-build-standalone and rv-ruby publish theirs; a Windows app with a symbolic link is refused, since Windows would unpack it as a text file.
- **Output.** The path of each archive, one per line, on standard output, and progress on standard error, so `fledge build | xargs ...` works (GNU Coding Standards, 4.8: diagnostics go to standard error).
- **Replacement.** A new build replaces `DIR/NAME-PLATFORM/` and its archive, as `cargo build` and `gem build` replace theirs.
- **What ships.** Everything in the project's root but `.git`, `.bundle`, `vendor/bundle`, `vendor/cache`, and the output folder, and the gems its Gemfile.lock locks for each target (ADR 005).
- **Option forms.** `--target=PLATFORM` and `--out=DIR` as well as the two-word forms, and `--` ending the options (GNU Coding Standards, 4.8; POSIX Utility Syntax Guideline 10).
- **`FLEDGE_RUNTIME_DIR`** names a folder of runtimes to use instead of downloading, as `PYTHON_BUILD_MIRROR_URL` and `RUSTUP_DIST_SERVER` redirect their tools.
- **The cache** is `$XDG_CACHE_HOME/fledge/runtimes`, or `~/.cache/fledge/runtimes`, on macOS as on Linux, as uv and pre-commit keep theirs.

### 3. A built app's launcher names itself and uses sysexits

When the launcher cannot start the app, it prints `NAME: what went wrong` on standard error, as Ruby prints `ruby: ...`, naming the app (`NAME.exe` on Windows) because the person who ran it never asked for Ruby. A windowed Windows launcher, which has no console, shows the same message in a message box unless standard error was captured. It exits with:

- **66 (`EX_NOINPUT`)** when the program the app runs, `app/ENTRY`, or the `fledge.cfg` that names it (ADR 005) is missing: the input it was to run does not exist.
- **70 (`EX_SOFTWARE`)** for anything else that stops it before the app runs: a runtime folder renamed to `bin` or `lib`, Ruby's DLL missing or damaged, a damaged `fledge.cfg`, gems Bundler cannot set up, a path too long, the environment unreadable.

Once the app runs, its exit status is the app's own, exactly as under `ruby main.rb`. macOS, Linux, and Windows use the same messages and statuses; `runtime/launcher/launcher.h` defines them once.

## Consequences

- `-V` no longer prints the version; it is an unrecognized option. Pre-1.0, with no users, the change is free (CHANGELOG).
- Scripts can tell a mistake in how they call `fledge` (2) from a build that failed (1), and a broken download of an app (66 or 70) from the app's own failure.
- The help header's SYNOPSIS is now load-bearing: it is the usage every usage error prints. `test/cli_test.rb` pins it.
- Delivery checks status 66 and the message on every operating system.
