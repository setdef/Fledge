# ADR 064: A Windowed App's Identifier Is the Developer's, and No Default Makes One Up

## Context and Problem Statement

macOS knows an app by its `CFBundleIdentifier`, and Windows by the AppUserModelID on a Start menu shortcut, before the app may notify anyone. Code signatures, desktop entries, `.deb` packages, and uninstall keys name the same string. The maintainer's decision 18 (`decisions.md`, 2026-10-26) puts what each system shows in the developer's hands (ADR 008). Where does an app's identifier come from?

## Decision Drivers

- macOS and Windows remember an app by its identifier, so a wrong one follows the app for good.
- A project with no `fledge.yml` still builds the console app it built before.
- Prior art: Tauri's required `identifier`; Briefcase's and Flatpak's required app IDs.

## Considered Options

1. The developer gives an `identifier` in `fledge.yml`, required for a windowed app (ADR 037) and optional for a console one.
2. Fledge makes one up by default, from the gemspec or the app's name.

## Decision Outcome

Chosen: option 1, because no default identifier could name a domain the developer controls, and a wrong one stays with the app. Tauri, Briefcase, and Flatpak also ask for it. No reason was recorded against option 2 beyond that.

A windowed app without an `identifier` fails to build, and the error suggests one: `io.github.OWNER.NAME` when the gemspec's homepage is on GitHub, as Flathub names such apps, or else `com.example.NAME`. A console app may have one, and on Windows it then becomes its AppUserModelID.

Confidence: high. Delivery reads every identifier back with each system's own tools on fresh computers.

### Consequences

- Good, because the identifier is the one key that ties a bundle, a Start menu shortcut, a code signature, a desktop entry, and a `.deb` package to one app (ADR 021).
- Good, because an app's identifier is a name its developer controls, not one Fledge guessed.
- Bad, because a windowed app's first build fails until its developer writes an identifier.

### Confirmation

`test/identity_test.rb` and `test/config_test.rb` hold the refusal, the suggestion, and the pattern. Delivery runs `examples/windowed_app` on fresh runners, and reads its bundle's identifier and its AppUserModelID (`.github/scripts/deliver-windowed.sh`, `.github/scripts/deliver-windowed.ps1`).
