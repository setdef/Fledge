# ADR 016: Sign With the Developer's Own Identity, Through --sign and Each System's Signer

## Context and Problem Statement

macOS's Gatekeeper refuses to open a downloaded app unless a Developer ID signature that Apple has notarized vouches for it, though a person can still open it through System Settings. Windows' SmartScreen warns about a downloaded program that no certificate it trusts has signed, and Smart App Control on Windows 11 checks every program and library a process loads. Every app Fledge builds runs where it lands, since a macOS bundle gets an ad hoc signature (ADR 008), but none is signed by anyone those checks trust.

The maintainer's decision 17 (`decisions.md`, 2026-10-26): "Ideally, fledge developers should have the option to make it so Windows/macOS don't block the use of the app. But not every app dev will have the done the required ceremony with Microsoft and/or Apple." How does a developer who has an identity sign with it, and what does a developer without one see?

## Decision Drivers

- Decision 17: signing is the developer's option, and unsigned builds keep working.
- A signing identity, its key, and its password are secrets, and `fledge.yml` is committed and shared.
- A signature seals what it covers, so signing comes after Fledge has written everything into the app and before the archive and the installers, which carry the signed files and are signed themselves.
- Each system's own signer (codesign, signtool) already takes an identity in its own form.

## Considered Options

1. One option, `fledge build --sign IDENTITY`, whose value each system's own signer takes as it is, as Briefcase's `--identity` does.
2. Signing settings in the app's configuration, as Tauri's `signingIdentity`, `certificateThumbprint`, `digestAlgorithm`, and `timestampUrl` are.

## Decision Outcome

Chosen: option 1, because one option covers both systems in each system's own terms, and keeps every identity out of a file other people build from.

On macOS IDENTITY is a code signing identity in the developer's keychain, by name or SHA-1 hash, as `codesign --sign` takes it. On Windows it is the SHA-1 thumbprint of a code signing certificate in the certificate store, as `signtool sign /sha1` takes it, hardware tokens included. Fledge reads no certificate, key, or password, and keeps none. A Linux build with `--sign` fails, since a Linux app carries no signature for its system to check, and a phone's build with it is a usage error, since Xcode and Gradle sign a phone's app. Without `--sign`, nothing changes.

Confidence: high that it signs as each system's tools verify, which CI proves with a self-signed identity; low that Gatekeeper and SmartScreen trust the result, which waits on the maintainer's own Developer ID and certificate.

### Consequences

- Good, because a developer with an identity signs with one option, and one without changes nothing.
- Good, because Fledge stores no secret, so a leaked `fledge.yml` or build log holds none.
- Bad, because the identity lives on one computer's keychain or store, so a CI that signs must import it there first.
- Bad, because a certificate kept in a cloud or a hardware service signs only through that service's own tool, which this option cannot reach; `--sign-command` reaches it on Windows (ADR 051).
- Bad, because a signing build depends on Apple's and DigiCert's timestamp servers, which can fail; Fledge runs codesign again when Apple's does not answer (`doc/contributors/design/signing.md`, "Timestamps").
- Neutral, because a signed macOS app runs under the hardened runtime with two entitlements (ADR 050), and notarization is a further option (ADR 033).

### Confirmation

`test/signing_test.rb` and `test/mac_signing_test.rb` hold the commands and refusals. CI makes a self-signed code signing identity in each run (`.github/scripts/make-test-identity.sh` and `.ps1`); the Build jobs build `examples/hello` and `examples/windowed_app` with `--sign`, and `test/built_app_test.rb` signs whole apps with `FLEDGE_TEST_SIGN_IDENTITY` (`-` signs ad hoc on any Mac). Delivery verifies them on fresh runners with codesign and signtool (`.github/scripts/deliver-signed.sh` and `.ps1`). The real trust chains are tests on `doc/contributors/account-tests.md`.
