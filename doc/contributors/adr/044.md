# ADR 044: Configure an App With an Optional fledge.yml

## Context and Problem Statement

Most apps build with no configuration at all: the program, its project, and NAME come from the project itself (ADR 005). Some must tell Fledge something the project does not say: a NAME the folder's name would not give, a windowed app's identity (ADR 008), its installers (ADR 009), several programs (ADR 024), libraries from the Linux distribution (ADR 030), a phone's host files (ADR 025). The maintainer accepted "configuration only where it's needed" (`decisions.md`, 2026-10-26, later, reply 2). Where, and in what format, does a project say these things?

## Decision Drivers

- Configuration only where it is needed: an app that needs none has no file.
- It works for every shape of project: a gem, an application with only a Gemfile, a lone `main.rb`.
- It stays out of what a gem publishes to RubyGems.org.
- Fledge reads it with Ruby's standard library, and adds no gem of its own to read it.
- A typo fails, rather than being silently ignored.

## Considered Options

1. An optional `fledge.yml` at the project's root, a YAML mapping, as RuboCop's `.rubocop.yml`, Kamal's `config/deploy.yml`, and Standard's `.standard.yml` are.
2. The gemspec's `metadata`.
3. A Ruby file Fledge executes, as Warbler's `config/warble.rb` is.
4. A TOML file.
5. A JSON file, as Tauri reads `tauri.conf.json`.
6. A section of a file the project already has, as Briefcase reads a section of the project's own `pyproject.toml`.

## Decision Outcome

Chosen: option 1, because it meets every driver, and options 2 to 4 each miss one. A gemspec's `metadata` (option 2) holds only strings, is published to RubyGems.org with the gem, and does not exist for an app with only a Gemfile. A Ruby file (option 3) is code to execute, not data to check. TOML (option 4) needs a gem Fledge does not depend on. Tauri's JSON (option 5) and Briefcase's `pyproject.toml` (option 6) were read as prior art, and no reason against them was recorded beyond YAML's being what Ruby tools use; JSON, like YAML, is in Ruby's standard library.

The file is optional. It is found at the root, and its presence also marks a root (ADR 005). Fledge refuses any key it does not know, naming it, so a typo or a removed key fails the build.

Confidence: high that it works; low that YAML is better than JSON or a section of another file, since those comparisons were not made.

### Consequences

- Good, because an app that needs nothing writes nothing, and every other app writes one small file, possible for any project shape.
- Good, because a wrapper can write a developer's `fledge.yml` or read it, and never sees a key silently ignored.
- Good, because Ruby developers already read YAML configuration, and editors validate it against Fledge's JSON Schema (`doc/contributors/design/public-interface.md`, "The fledge.yml schema").
- Bad, because YAML has its own surprises (`no` read as false, unquoted versions read as numbers); `Fledge::Config` checks each value's type and says what it wanted.
- Bad, because every key is a promise: `fledge.yml` is part of what 1.0 freezes (ADR 029), so a key is added only when an app needs it.
- Neutral, because the keys are documented in `lib/fledge/config.schema.json`, which a test keeps true to `Fledge::Config`.

### Confirmation

`test/config_test.rb` covers each key and the refusal of unknown ones; `test/config_schema_test.rb` fails when the schema and `Fledge::Config` disagree.

## More Information

The keys: `lib/fledge/config.schema.json` and `doc/contributors/design/public-interface.md`.
