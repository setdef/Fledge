# ADR 007: An App's Gems Are Its Developer's, Licenses and All

## Status
Accepted (requested). Agents wrote this ADR and may change it (AGENTS.md, Questions). It applies the maintainer's words of 2026-10-28 in `doc/contributors/decisions.md`: "Why does it refuse GPL and AGPL gems? That's up to the app dev to decide, not up to Fledge. In fact, why is Fledge taking any kind of opinion at all about what license the gems the app dev uses are under?" It supersedes every part of ADR 004, ADR 005, and ADR 006 that judged an app's gems by their licenses: ADR 004, section 7, and the part of section 8 about an app's gems; ADR 005, section 3's `licenses` and `compiled` keys, and section 7; ADR 006, section 8's license checks (its linkage check stays), section 9's refusal of nokogiri on Windows, and section 10. Decision 8 and the replies of 2026-10-26, later, still govern everything Fledge itself puts into an app, its runtime, exactly as ADR 004 says.

## Date
2026-10-28

## Context

Decision 8 asks that a developer who buys a commercial license be able to ship an app with no copyleft obligation beyond notices. Agents applied it to everything `fledge build` copies into an app, the app's own gems included, and built a license regime for them through 0.0.1.pre.4:

- every gem had to be under a license that asks nothing beyond notices, or the LGPL; a GPL or AGPL gem (Tokra, say), an MPL gem, a gem with an unknown license, and one that declared none failed the build, unless `fledge.yml` restated its license under `licenses`;
- an LGPL gem shipped only when its exact source was pinned, which for a precompiled build meant locking its `ruby` build too;
- every compiled file of every gem was read for the code of known copyleft libraries (GNU libiconv, libxcrypt, GNU MP), which failed the build when compiled in, whatever anyone declared, so nokogiri's precompiled macOS and Windows builds, and its Windows build from source, could not ship;
- every other compiled file had to be attributed, to the libraries `lib/fledge/compiled_code.yml` said its reviewed builds held or to what `fledge.yml` declared under `compiled`, or the build failed;
- every Rust crate a Rust extension compiled in, or ran while compiling, was read with `cargo metadata` and judged the same way (`Fledge::RustCrates`);
- each app carried `notices/GEMS.txt`, Fledge's account of each gem's license, of the libraries its compiled files held, and of what the LGPL asked, with a warning for a gem that shipped no license file.

The maintainer's words end all of it. An app's gems are the developer's choice, and so is whether their licenses suit the app; Fledge is a tool that ships what the developer chose. Decision 8 protects developers from obligations Fledge would add on its own, through its runtime, which no developer chose and none can remove; a gem in the Gemfile is there because the developer put it there.

Prior art, read for this decision:

- **PyInstaller** says that what it builds "can be shipped with whatever license you want, as long as it complies with the licenses of your dependencies" (`pyinstaller/pyinstaller` at 4469721, `doc/license.rst` lines 15 to 17), which leaves the dependencies' licenses to the developer. Its build writes no notices for them: the only license file `PyInstaller/building/` names is Tk's own `license.terms`, which it collects among the Tcl/Tk files its splash screen needs and does not miss when absent, since "this file has no effect on operation of splash screen" (`splash.py`, lines 213 and 256 to 260).
- **Tauri's bundler** takes only the app's own license and license file (`tauri-apps/tauri` at 32576120f, `crates/tauri-bundler/src/bundle/settings.rs` lines 651 to 655) and nothing about the crates the app depends on; collecting their notices is left to tools a developer chooses, such as cargo-about.
- **Warbler** packs an app's gems as they are installed, with their own files, and its `lib/` has no license handling at all (`jruby/warbler` at 3196d5f).
- **Bundler** offers `bundle licenses`, which prints the license each gem's specification declares, or "Unknown", as information, with no verdict (`bundler/cli.rb` lines 558 to 570, at Bundler 4.0.20).

## Decision

### 1. Fledge judges no gem by its license

`fledge build` ships every gem the lockfile locks for the target, whatever its license, whether or not it declares one, and whatever its compiled files hold. `Fledge::AppGems` no longer reads a gem's license; `Fledge::CompiledCode`, its map `lib/fledge/compiled_code.yml`, and `Fledge::RustCrates` are gone, and with them the reviewed gems, the copyleft signatures for an app's gems, and the requirement to declare compiled code nobody reviewed. `Fledge::LicensePolicy`, `Fledge::Binary`, `tasks/license_audit.rb`, and `runtime/licenses.yml` stay as they are, for the runtimes (ADR 004); `Fledge::LicensePolicy` lives in `lib/` still, though only the audit reads it now.

### 2. What fledge build still checks, and why none of it is a license opinion

Each remaining check decides whether the app runs where it goes, or whether its inputs are the ones the developer locked:

- **A build for each target.** The lockfile must lock the target, as the app's frozen Bundler would refuse it otherwise (ADR 005, section 6), and a gem with an extension to compile is compiled only on its own platform, failing for any other, since a cross-build has no toolchain for it (ADR 006, section 1).
- **Checksums and git pins.** Each `.gem` must match the lockfile's SHA-256 and each git gem must be locked to a whole commit, because Fledge pins every external input (AGENTS.md); this is about which bytes ship, not what they are licensed under.
- **`required_ruby_version`, the Gemfile's `ruby`, and path gems.** A gem whose `required_ruby_version` excludes the runtime's Ruby, a Gemfile `ruby` the runtime does not satisfy, a path gem outside the project, a path gem with an extension (which Bundler never compiles), and git submodules each fail, because RubyGems or Bundler would refuse them, or the app could not carry them, on the computer it goes to.
- **Linkage** (`Fledge::Linkage`, the part of ADR 006, section 8, that stays): a compiled file may need only libraries the target's operating system provides (on Linux, those a manylinux_2_39 wheel may assume), the runtime ships, or the gem carries; anything else would fail to load on another computer, with an error that names a gem, which a person running the app must never meet (AGENTS.md, Design precedence 1). It reads only what each file needs, never what is compiled into it.
- **The oldest macOS and glibc** a gem Fledge compiled needs (ADR 006, section 4), which must be the runtime's, or the app would not start on the systems the runtime supports.

Two behaviors once given license reasons stay for technical ones. A git gem ships its own folder of the checkout, not the whole repository (ADR 006, section 7): Bundler finds the gem by its gemspec there alone, and a repository can hold symbolic links a Windows `.zip` cannot. The runtime's pruning of nkf's JRuby sources (ADR 004, section 6) is about the runtime, which decision 8 still governs.

### 3. notices/GEMS.txt is gone

Fledge writes no notices of its own for an app's gems. Each gem ships as RubyGems or Bundler installs it, with all of its own files, its license files among them, in the runtime's gem folder, its specification, which declares its license, in `specifications/`, and its `.gem` in `cache/`; a git gem's folder is shipped whole. Every notice a gem's author put in it travels with it, unchanged, as it would under Warbler or PyInstaller.

GEMS.txt went further than any packager in the prior art, and the further parts were Fledge's opinions: which license a gem was "really" under, which libraries its binaries held, what the LGPL asked of the developer for it, and a warning when a gem carried no license file. A version reduced to names, versions, declared licenses, and copied license files would only restate what each gem's folder and `bundle licenses` already give, in a file whose presence suggests that Fledge stands behind it. `doc/licensing.md` tells developers where their gems' notices are in the app, that `bundle licenses` lists the declared licenses, and that their gems' licenses are theirs to comply with. Each app's `notices/` holds what Fledge itself put there: `NOTICES.txt` and the SBOM of its runtime.

### 4. fledge.yml knows only name

`licenses` and `compiled` existed only to answer Fledge's own license questions, so they are removed; a `fledge.yml` that still has either fails the build, as any key Fledge does not know does, so a stale file is noticed rather than silently ignored. Pre-1.0, with no users, there is no compatibility shim; CHANGELOG.md says so.

### 5. The examples and CI ship what Fledge once refused

`examples/native_app` adds spreadsheet 1.3.5, pure Ruby under `GPL-3.0`, whose dependency bigdecimal 4.1.3 Fledge compiles, beside ratatui_ruby (LGPL-3.0-or-later), and Build from source and Delivery run it on all four platforms. `examples/nokogiri_app` builds from source on Windows, with GNU libiconv linked in, and Delivery runs it there, as it does on macOS. `test/gem_app_build_test.rb` builds a GPL gem, an AGPL native gem shaped like Tokra, a gem that declares no license, a precompiled LGPL gem whose source is not pinned, an MPL gem, one whose license SPDX does not know, and a native gem with GNU libiconv's code compiled in, and requires all of them to ship without a word; `test/native_gems_test.rb` requires every one of nokogiri's real precompiled builds, libiconv and all, to pass the linkage check. CI's Licenses jobs still plant a GPL gem in each runtime and require the audit to fail: that gem would be Fledge's, not the developer's.

## Consequences

- A developer who buys a commercial license still gets a runtime with no copyleft obligation beyond notices; whether the app as a whole has one depends on the gems they chose, which is theirs to judge, with their own lawyer if they need one.
- Fledge no longer warns a developer that a precompiled gem compiles in an LGPL library (nokogiri's macOS and Windows builds, which say so in their own `LICENSE-DEPENDENCIES.md`); the gem's own notices are where that fact lives.
- `fledge build` no longer needs `cargo metadata` after compiling a Rust gem, and no map of reviewed gems goes stale when a gem publishes a new version.
- About 2,000 lines of library code, map, signatures, and tests are gone, and with them a class of build failures that had nothing to do with whether the app runs.
