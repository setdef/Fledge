# ADR 021: Offer a .deb, Opt-In, Built by dpkg-deb

## Context and Problem Statement

A Debian or Ubuntu user installs software with `apt`, which tracks what a package put on the computer and removes exactly that. An AppImage (ADR 009) is a file to run, not an installation: it adds no menu entry of its own, and `apt` knows nothing of it. The `.deb` was the cheapest of the installers left for later, and the maintainer answered the orchestrating agent's briefing on 2026-11-02 (`decisions.md`): "Go for .deb".

How should Fledge make a `.deb`, and should every windowed Linux app get one?

## Decision Drivers

- The maintainer asked for a `.deb`.
- Code is a liability: a maintained tool beats a format writer of Fledge's own (ADR 010).
- A build that passes today on a Linux computer should still pass.
- A package should install only where the app runs, and say why when it will not.

## Considered Options

1. A `.deb` that `dpkg-deb` packs from a tree and a control file Fledge writes, as Briefcase makes one, asked for in `installers`.
2. The same `.deb` in the default set, beside the `.dmg`, the setup program, and the AppImage.
3. A `.deb` written by Fledge's own tar and `ar` writer, as Tauri's bundler writes one.

## Decision Outcome

Chosen: option 1, because `dpkg-deb` is Debian's own maintained tool, which every Debian and Ubuntu has, and because a default that needed it would make every Linux computer without it (Fedora, Arch, and the rest) fail builds that pass today, to make a package for a family that computer is not in.

`installers` takes `deb` beside `dmg`, `nsis`, and `appimage`. A developer who ships to Debian and Ubuntu lists `installers: [appimage, deb]`. A `deb` builds on the glibc Linux platforms, `x86_64-linux` and `aarch64-linux`, and builds nothing on musl, so one list serves every platform. The package is named for the app's identifier in lower case, depends on the glibc the runtime needs, and installs the app under `/usr/lib` with its desktop entry and icons where desktops look. Its control file is a stanza of text, an input to `dpkg-deb`, not a format Fledge writes.

Confidence: high. Delivery installs the package with `apt` on fresh Debian and Ubuntu, runs it, and removes it.

### Consequences

- Good, because a Debian or Ubuntu user installs the app with `sudo apt install ./NAME-PLATFORM.deb`, finds it in their menu, and removes all of it with `apt remove`.
- Good, because `apt` refuses the package on a Debian or Ubuntu older than the runtime's glibc, saying which dependency it cannot meet, where a package without it would install and fail when run.
- Bad, because a computer without `dpkg-deb` fails the build when `deb` is asked for; the error says to install dpkg.
- Bad, because a `.deb` that lists the libraries its gems load (ADR 030) names the packages of the distribution it was built on, which another distribution may name differently.
- Bad, because the package is unsigned: `apt` installs a local file without a signature, and a repository is a channel Fledge does not run.
- Neutral, because a name with spaces is no command, so no program is linked into `/usr/bin`.

### Confirmation

`test/deb_test.rb` holds the tree, the control file, and the refusals. `.github/scripts/deliver-deb.sh` runs in `debian:trixie-slim` and `ubuntu:24.04` containers, which hold no Ruby, on x86_64 and aarch64 runners: it reads the fields with `dpkg-deb`, installs with `apt-get install`, checks the files, the desktop entry, and the icons, runs the program as root and as `nobody`, removes the package, and fails if anything is left or `dpkg --audit` reports anything.
