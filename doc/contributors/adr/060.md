# ADR 060: `fledge build` takes the phone as its first operand

## Context and Problem Statement

`fledge build [PATH]` builds an app for the computer it runs on (ADR 010). For a phone, it writes a project instead (ADR 012), and a developer has to say which phone. Where on the command line, or in the project, does that go?

## Decision Drivers

- Which phone to build for is a question of each build, as which desktop is, not a property of the app.
- One build makes one output, on a computer that can make it: iOS's project needs a Mac, Android's a computer Google's SDK runs on.
- Prior art: Briefcase's `briefcase create iOS` and Flutter's `flutter build ios` name the platform as an operand.
- GNU's conventions for operands and options (ADR 002).

## Considered Options

1. The phone's name as the first operand: `fledge build ios [PATH]`, `fledge build android [PATH]`.
2. A `targets:` key in `fledge.yml`.
3. An option, such as `--ios`.
4. A command of its own, as Tauri's `tauri ios build`: `fledge ios build`.

## Decision Outcome

Chosen: option 1, because it names the platform where Briefcase and Flutter do, and keeps one command for what is still a build. A `targets:` key would make one build write several outputs that need different computers. No prior art read uses an option. A second command, as Tauri's, splits one action in two.

A first operand named `ios` or `android` is the phone. A folder of that name is written `./ios`, or follows `--`. Each phone's project is built where its tools run: iOS on a Mac (`arm64-darwin`), since only Xcode builds for it; Android on a Mac, x86-64 Linux, or Windows, where Google supports its SDK. `aarch64-linux` is left out, since Google publishes no Android SDK build tools for it. Elsewhere `fledge build` says where to build the project and exits 1.

Confidence: high. The help header, the CLI's tests, and CI's Mobile apps jobs all use this form.

### Consequences

- Good, because `fledge.yml` gains no key for it, and a desktop build is unchanged.
- Good, because a developer's CI runs one build per phone on a runner that can build it, as it does per desktop.
- Bad, because a project folder named `ios` or `android` needs `./` or `--`, and the help header says so.
- Bad, because `ios` and `android` are words the operand reserves.

### Confirmation

`exe/fledge`'s help header documents `fledge build ios|android [OPTIONS] [PATH]`. `test/cli_test.rb` and `test/mobile_build_test.rb` test the operand, the `./ios` form, and the refusal on a computer that cannot build the phone's project. `test/mobile_platform_test.rb` tests `MobilePlatform::HOSTS`.
