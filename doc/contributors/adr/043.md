# ADR 043: Each Runtime Carries the Sources Its Licenses Ask For, in notices/sources/

## Context and Problem Statement

Some components a runtime ships ask that their source go with them. libxcrypt and GNU MP are LGPL libraries (ADR 042). AppImage's runtime, in a Linux runtime's `tools/`, has libfuse (LGPL-2.1) linked in, and NSIS's LZMA module, in a Windows runtime's `tools/`, is under the Common Public License, which asks that a binary say where its source is (ADR 049).

The maintainer accepts a source offer for "the LGPL'ed library" ("latter is fine and normal"), "as long as we're clear about that to app devs" (`decisions.md`, 2026-10-26, later). The LGPL binds whoever conveys the library, and that is the app's developer, who conveys it inside the app. If the only copy of the source is on a host, their compliance depends on that host keeping its terms and staying up, and on Fledge never deleting a release. Where should the source be?

## Decision Drivers

- The developer's compliance should depend on no host, Fledge's included.
- Whoever receives only the app should be able to rebuild and replace each library from what they received.
- The source must be exactly what the runtime's copy was built from, checked by SHA-256.
- The license audit must see every file the runtime carries (ADR 004).

## Considered Options

1. **Carry the sources inside the runtime,** in `notices/sources/`, one folder per component, so every app has them; and keep publishing the release's source bundle beside each runtime.
2. **The release's source bundle as the only copy,** named by every app's NOTICES.
3. **Point at upstream's own archives by their pinned SHA-256.**

## Decision Outcome

Chosen: option 1, because it alone needs no host at all. LGPL-2.1, section 6(a), names that way: "Accompany the work with the complete corresponding machine-readable source code for the Library". GPL-3.0, section 6, which LGPL-3.0 uses for GNU MP, likewise lets source go with the object code on the same medium (6(a)) or "in the same way through the same place" (6(d)). The release bundle alone, and upstream's archives, each leave a host the only place the source can be had (commit e84189e).

Each folder holds the pinned archive exactly as downloaded, its license texts, and `BUILD.txt`, which says how the runtime's copy was built and how to replace it. The runtime builder writes it before the audit, so the audit, the SBOM, and NOTICES see it. Every app copies the runtime's `notices/` whole, and every installer holds the app, so an app that keeps its `notices/` folder carries the source wherever it goes. NOTICES names the folder in the app first and the release's bundle second. Releases are never deleted, since every NOTICES links its bundle there.

Confidence: high. CI checks every Linux and Windows app for each folder, and builds a replacement libxcrypt from the source inside the app it replaces it in.

### Consequences

- Good, because a developer who ships the app ships the source with it, whatever becomes of GitHub or of Fledge.
- Good, because a person who received only the app can rebuild its libxcrypt, and its AppImage's runtime with another libfuse.
- Bad, because each Linux and Windows runtime grows by about 4 to 5 MB, the size of its sources, which are already compressed. "Tiny filesize is not a priority" (decision 20).
- Bad, because a console app for Linux or Windows carries the installer tools' sources too, though it never holds the tools: `notices/` is one folder for every app.
- Bad, because the sources exist twice per release, in the runtime and in the bundle, and CI must keep them identical.
- Neutral, because macOS and the phones ship nothing whose source is asked for, and carry no `notices/sources/`.

### Confirmation

- The license audit owns each folder by a component of kind `source` in `runtime/licenses.yml`, allowed only for a pinned source and only for uncompiled files under `notices/sources/`; any other file there fails as unaccounted.
- CI's "Licenses" jobs compare `notices/sources/` with the release's source bundle file by file, and fail when a platform that ships no such component carries the folder.
- Delivery checks each Linux and Windows app holds each folder with the archive its `BUILD.txt` names, and that its NOTICES names the folder; CI's "Replace libcrypt" builds from the app's own copy.
