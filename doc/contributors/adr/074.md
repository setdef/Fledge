# ADR 074: fiddle and the ffi gem work on both phones

## Context and Problem Statement

Ruby's `fiddle` and the `ffi` gem call C functions by name and turn Ruby blocks into C callbacks, through libffi. Fledge left fiddle out of the iOS runtime, citing only xord/cruby's comment that it does so "to pass the App Store review" (Rakefile line 577 at 11d62c4), and no phone build compiled the ffi gem. The maintainer asked why neither works on both phones, and agreed to check that reason and, if it fails, support both (`decisions.md`, 2026-11-12): a reason to leave either out must be cited, not assumed.

The check (`doc/contributors/research/2026-11-12-ffi-and-fiddle-on-phones.md`) found nothing that forbids them. App Review Guidelines 2.5.1 and 2.5.2 (read 2026-11-12) govern which functions an app calls and whether it downloads code, and name no FFI; `dlopen` and `dlsym` are public in the iPhoneOS SDK. CPython's iOS build compiles `ctypes` against libffi (v3.13.0, `iOS/README.rst` lines 179 to 188), and BeeWare's iOS Python and Pythonista ship it. On Apple's arm64, libffi makes closures from a pre-signed page remapped with `vm_remap` (`closures.c` lines 161 to 245), so no page is both writable and executable. How do a phone's runtime and build carry them?

## Decision Drivers

- The app's code runs as under `ruby main.rb` (decisions 9 and 20; the maintainer's words of 2026-11-12 on differences): `require "fiddle"` and a locked ffi gem work as on a desktop.
- A difference is accepted only where a platform truly forbids it, shown from primary sources.
- Fledge changes no developer's gem (ADR 007), and adds no code of its own for one gem.

## Considered Options

1. fiddle in the iOS runtime with libffi linked into fiddle's own object and kept local to it, as Android's `--exclude-libs` keeps it; the ffi gem compiled through its own `extconf.rb` with the libffi it bundles.
2. One libffi, global in the runtime, which both fiddle and the ffi gem use.
3. Keep fiddle out of iOS, and refuse the ffi gem on phones.

## Decision Outcome

Chosen: option 1, because each copy of libffi stays private to what uses it, so the ffi gem's own copy cannot collide with fiddle's, and the ffi gem builds as on a desktop with no Fledge code for it. Three general changes to the phone build make that so, for any gem: the link takes the Makefile's `LOCAL_LIBS` as make expands it, the build's environment names the phone's tools as `CC`, `CXX`, `AR`, and `RANLIB`, and `PKG_CONFIG` is false, so the computer's own libffi never reaches a phone slice. How: `doc/contributors/design/phone-projects.md` and `phone-runtimes.md`.

Option 2 needs the runtime to export libffi and its headers, which Android's runtime hides, and the ffi gem's system-libffi path. Option 3 rests on a reason the check found unfounded.

Confidence: high for fiddle: the iOS parity check passes on CI's iPhone and iPad Simulators with fiddle's justifications removed. Medium for the ffi gem: `examples/ffi_phone` ran on CI's Simulators and Android emulators, but its build took a computer's own libffi where one was installed, and its link of `LOCAL_LIBS` misread a Windows path, so it was reverted; the defect and its fix are in `doc/contributors/design/phone-projects.md`, "The ffi gem". App Review has not seen such an app: that is the maintainer's account test IOS-3 (`doc/contributors/account-tests.md`).

### Consequences

- Good, because `require "fiddle"` and gems that use ffi, such as ffi's own users, work on both phones, and fiddle is compared with stock Ruby there.
- Bad, because a gem whose Rakefile builds a library for ffi to load (llhttp-ffi, scrypt) is still refused by name: Fledge would have to install the Rakefile's build dependencies for this computer, link an iOS library as a framework, since iOS takes no loose library, and make the path the gem gives `ffi_lib` reach it.
- Bad, because whether App Review accepts an app that carries fiddle or ffi is untested.

### Confirmation

The mobile parity check compares fiddle, and the iOS runtime's build fails if libffi's symbols leave fiddle's object. The ffi gem's confirmation, `examples/ffi_phone` in the Mobile apps jobs, returns with its fix.
