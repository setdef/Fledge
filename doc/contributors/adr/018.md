# ADR 018: Windows on ARM64, From RubyInstaller's ARM64 Build

## Status
Accepted (requested). Agents wrote this ADR and may change it (AGENTS.md, Questions). It applies the maintainer's decision 22 in `doc/contributors/decisions.md` ("I'd like to support Windows on ARM (and Linux on ARM) eventually, but it's not a blocker to continuing to iterate. It may be a blocker to 1.0 though.") and is Plan 002's story "Windows on ARM."

## Date
2026-11-01

## Context

Windows 11 on ARM64 runs `x64-mingw-ucrt` apps under emulation, more slowly, and runs native ARM64 programs at full speed. RubyGems names the native platform `aarch64-mingw-ucrt`, what RubyInstaller's ARM64 Ruby reports.

RubyInstaller publishes that build beside its x64 one, from the same release and signed with the same key: `rubyinstaller-4.0.9-1-arm.7z` (RubyInstaller-4.0.9-1). Its tree has ADR 001, section 8's shape: `bin\aarch64-ucrt-ruby400.dll`, `ruby.exe`, `rubyw.exe`, `bin\ruby_builtin_dlls\` with GNU MP and winpthreads, and OpenSSL, libyaml, zlib, and libffi beside the extensions that load them. MSYS2's CLANGARM64 environment built it, with LLVM rather than GCC, so no libgcc is in it; its `libgmp-10.dll` is byte for byte the one in MSYS2's `mingw-w64-clang-aarch64-gmp-6.3.0-2` package, built from the same source package as the x64 one. llvm-mingw, which already compiles the x64 launcher from Ruby's headers (ADR 001, section 8), targets `aarch64-w64-mingw32` from the same toolchain. GitHub's `windows-11-arm` runners run ARM64 Windows, and `ruby/setup-ruby` installs RubyInstaller's ARM64 Ruby there with its MSYS2.

A spike (the `experiment/signing` branch's runs of 2026-11-01) built an `aarch64-mingw-ucrt` runtime on a Mac and on Linux, passed it through the license audit, and built and delivered hello, the console probe, and the windowed app with its installer on a `windows-11-arm` runner, with parity between the built probe and `ruby.exe main.rb` on both code pages.

## Decision

### 1. One more target, built as the x64 one is

`Fledge::Platform` adds `aarch64-mingw-ucrt`, a Windows platform, so everything Windows does applies: `NAME.exe`, the `.zip`, the GUI launcher for a windowed app, rcedit's version information and icon, the NSIS installer, and `--sign` with the Windows SDK's ARM64 signtool (ADR 016). `runtime/sources.yml` pins RubyInstaller's ARM64 archive, its signature, and the key, which is the x64 archive's; the Windows recipe cross-compiles the launcher with llvm-mingw for `aarch64-w64-mingw32`, on Linux in CI or on a Mac. The runtime's tools stay the x64 and x86 programs they are (rcedit, NSIS, LLVM's `llvm-readobj`), which Windows 11 on ARM64 runs under its own emulation; none ships in an app.

### 2. What differs, and why

- **GMP**: the license audit pins the ARM64 `libgmp-10.dll` by its own SHA-256, and the release's source bundle names MSYS2's CLANGARM64 package, which CI checks holds the runtime's DLL byte for byte, and the same source package, and says how to build a replacement for `aarch64-w64-mingw32`. CI builds a replacement GMP with llvm-mingw for ARM64 and runs hello with it on an ARM64 runner, as it does for x64 (Replace GMP).
- **No libgcc**: LLVM built RubyInstaller's ARM64 tree, so `runtime/licenses.yml` lists no GCC runtime for it; the MinGW-w64 runtime, winpthreads, and the rest are as on x64.
- **makensis under emulation**: Windows on ARM64's x86 emulator keeps a cache service (XtaCache) that holds an emulated program's file open for a while after it exits, so the build's own folder could not be deleted after NSIS ran. `Fledge::Nsis` runs makensis from a copy in the system's temporary folder, which it removes as far as Windows lets it.
- **Gems**: sqlite3 2.10.2 publishes no `aarch64-mingw-ucrt` build, and its source does not compile there (SQLite's own `configure` does not know `aarch64-w64-windows-gnu`), so `examples/my_cool_app`, and the parity check's gem-shaped probe, which uses its Gemfile, do not run on ARM64 Windows; the parity check says so and checks the plain probe on both code pages. A gem that publishes an `aarch64-mingw-ucrt` build, or compiles there, ships as on x64 (ADR 005, ADR 006).

### 3. Proven natively

CI builds the runtime on Linux, audits it and RubyInstaller's whole ARM64 tree (whose expectations match x64's), and on `windows-11-arm` runs the tests, the parity check, and the console's Ctrl-C reference; builds hello, the probes, and the windowed app, signed and unsigned; and delivers them on a fresh ARM64 runner: `deliver.ps1`, the console's Ctrl-C on both code pages and the windowed app from a console (ADR 015), the windowed app's identity, its installer's Start menu shortcut and AppUserModelID, and the signed build's verification (ADR 016). `installed.yml` installs Fledge from each tag on `windows-11-arm` and delivers hello and the windowed app with the runtime from the release.

## Consequences

- An app runs natively on Windows 11 on ARM64; its developer builds it on such a computer, as each platform's app is built on that platform (ADR 010).
- Gems without an ARM64 Windows build that will not compile there keep an app off ARM64 Windows, as on any platform a gem does not support.
- The runtime's x86 and x64 tools run emulated on ARM64; native builds of rcedit and NSIS would remove that, when they exist.
