# ADR 005: Ship the Program the Developer Already Runs, With Its Project

## Context and Problem Statement

A Ruby developer already has an entry point. A gem has `exe/my_cool_app`, an application has `bin/server`, a script is a `main.rb`, and each runs from its project's root, where the Gemfile or gemspec is. Fledge first shipped only a folder with a `main.rb`, which asked every developer to reshape a project before it could ship. What should `fledge build` take as the app, and how does it find the rest of the project the program needs?

## Decision Drivers

- The app's code stays as it is without Fledge (`decisions.md`, 2026-10-26, decision 9): a gem-shaped program that says `require "my_cool_app"` and reads files of its project at run time keeps working.
- "my ruby code just works" outranks a small app (decision 20).
- Configuration only where it is needed.
- NAME, in `dist/NAME-PLATFORM`, should be the app's own name: "My instinct is to use the app's primary class/module's name, like MyCoolApp." (decision 5).

## Considered Options

The orchestrating agent offered four, recorded with the maintainer's reply in `decisions.md`, 2026-10-26, later, reply 2:

1. (b) The executable the developer already runs, such as `exe/my_cool_app` or `bin/server`, with the project root where the Gemfile or gemspec is.
2. (a) A folder with a `main.rb`, as Fledge first shipped and LÖVE's fused games do.
3. (c) A configuration file naming the entry point.
4. (d) The gemspec's `executables`.

## Decision Outcome

Chosen: option (b), "the executable you already run", with configuration only where it is needed and NAME taken from the project, which configuration may override. The orchestrator recommended it and the maintainer answered "Ok." (`decisions.md`, 2026-10-26, later, reply 2). It alone ships every shape a Ruby project already has without asking the developer to move a file: (a) and (d) remain as cases of it (a folder means its gemspec's one executable, or else its `main.rb`), and (c) is needed only where nothing else says which program to run.

`fledge build PATH` takes the program to ship. The project's root is found from the program upward as Bundler finds a Gemfile, and everything in the root ships but what belongs to the developer's computer or to earlier builds. NAME is `fledge.yml`'s `name`, else the root's gemspec's name, else the root folder's name, camelized as Bundler's gem template names a module (`my_cool_app` is `MyCoolApp`).

Confidence: high. CI builds the desktop examples and the parity probe this way, `examples/hello` on every desktop platform and `examples/my_cool_app` on every one but ARM64 Windows, and the rules follow Bundler's own.

### Consequences

- Good, because a gem, an application, and a lone script each build with no change to their layout, and the program's `$0`, `__FILE__`, and `require` behave as under `ruby` or `bundle exec` (ADR 081, ADR 095).
- Good, because an app that reads a file of its project at run time finds it, since the whole project ships.
- Good, because NAME is the app's own name everywhere, as decision 5 asked; `examples/hello` ships as `Hello`.
- Bad, because an app carries files it may never read (tests, docs), which costs size; decision 20 accepts that.
- Bad, because the root walk needs rules of its own: it stops at a folder holding `.git`, refuses the developer's home folder, and leaves out tagged build folders, so a stray marker file or an old build cannot pull the wrong files in. Each rule is one more thing to keep true to Bundler.
- Bad, because a project nested inside another project, as `examples/hello` is inside Fledge's own gem, needs a `fledge.yml` to mark its root.
- Neutral, because a name no operating system can use for a program fails the build and asks for `name` in `fledge.yml` (ADR 044).

### Confirmation

`test/app_test.rb` covers the entry point, the root walk, what ships, and NAME; `test/cache_tag_test.rb` covers the build folders left out. CI's Build and Delivery jobs build `examples/hello` (a `main.rb`) on every desktop platform and `examples/my_cool_app` (a gem's `exe/`) on every one but ARM64 Windows, and the parity check compares the gem-shaped app with `bundle exec ruby exe/my_cool_app`.
