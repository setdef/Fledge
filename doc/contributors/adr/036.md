# ADR 036: Name Targets by Their RubyGems Platform

## Context and Problem Statement

Fledge has a runtime per platform, and names each platform in many places: the runtime's asset, `fledge build`'s output, `dist/NAME-PLATFORM`, error messages, CI's jobs, and the license map. Which names should those be?

## Decision Drivers

- A Ruby developer should meet names they already know.
- The name decides which precompiled gem fits a runtime, so it must say what RubyGems and Bundler say.
- One name per platform, the same everywhere Fledge prints it.

## Considered Options

1. **RubyGems platform names:** `arm64-darwin`, `x86_64-linux`, `aarch64-linux`, `x86_64-linux-musl`, `aarch64-linux-musl`, `x64-mingw-ucrt`, and `aarch64-mingw-ucrt`.

## Decision Outcome

Chosen: option 1, because they are the names Ruby developers already meet in `Gemfile.lock` and in precompiled gems, and the names that decide which precompiled gem fits a runtime. No alternative was weighed when this was decided. The section below reports alternatives found later; they were never the reason.

A build's target is the platform Fledge runs on (ADR 010), which `Fledge::Platform.local` maps from `Gem::Platform.local`. The phones' targets follow RubyGems' grammar but are chosen so that no desktop gem fits them (ADR 057).

Confidence: high that the names work: `fledge build` matches gems by them on every platform in CI. No recorded comparison says they are better than the alternatives below.

### Consequences

- Good, because a lockfile's `PLATFORMS` section, `bundle lock --add-platform`, and a gem's platform suffix all say what `fledge build` says.
- Good, because a new platform's name is settled by RubyGems, not by Fledge.
- Bad, because RubyGems' names are irregular: `arm64` on macOS against `aarch64` on Linux and Windows, `x64` on Windows against `x86_64` elsewhere. A developer who knows Rust's or Go's names must learn these.
- Bad, because a Mach-O gem may also be named for a macOS version (`arm64-darwin-23`), which fits a runtime only as RubyGems decides; `fledge build` must match as RubyGems does, not by string.

### Confirmation

- `Fledge::Platform::NAMES` lists the names, and `test/platform_test.rb` checks that each maps from `Gem::Platform` as RubyGems reports it.
- The asset names in `RuntimeBuilder#assets` and `Fledge::Runtimes.file_name` take the name as it is.

## More Information

- Asset names: `doc/contributors/design/runtimes.md`, "Asset names".

### Later research (2026-11-10)

These alternatives were looked up after the decision. They inform a reader; they were never its reason.

- **LLVM target triples,** which Rust uses: `aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`, `x86_64-pc-windows-msvc`. Tauri's `--target` takes one, and chooses only the compiler's target with it, not another system's package (Tauri's CLI documentation).
- **Go's GOOS and GOARCH:** `darwin/arm64`, `linux/amd64`, `windows/arm64`, two words with one spelling each.
- **Python's wheel platform tags** (PEP 425, PEP 600, PEP 656): `macosx_14_0_arm64`, `manylinux_2_39_x86_64`, `musllinux_1_2_aarch64`, `win_amd64`, which name the oldest system and the C library in the tag.
- **Electron's tooling:** electron-packager and electron-builder take `--platform darwin|linux|win32` and `--arch x64|arm64`, Node's `process.platform` and `process.arch`.

Each would be regular where RubyGems' names are not, and none would tell a Ruby developer which precompiled gem fits.
